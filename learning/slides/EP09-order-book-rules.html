01 · 订单簿结构

两排队伍：卖盘在上，买盘在下

卖盘：价格从低到高
买盘：价格从高到低
最好的价格离中间最近
一行 = 一个价格档位
档内订单按到达顺序排队
100.10 档：S1 → S2
Maker 挂单方
在簿里等待，提供流动性
比喻失效处：菜市场能讨价还价。撮合引擎不会，成交价 = Maker 价格。
价差 Spread
0.10
100.10 − 100.00
Taker 吃单方
一到就成交，消耗流动性
  1. 来看一个示例订单簿。它分成两半。上面红色的是卖盘，下面绿色的是买盘。
  2. 卖盘按价格从低到高排，最便宜的卖单离中间最近。买盘反过来，出价最高的离中间最近。
  3. 卖一价是 100.10，买一价是 100.00。两者之差 0.10，就是价差。价差越小，市场越活跃。
  4. 每一行叫一个价格档位。同一档里可能有好几个订单，按到达顺序排队。比如 100.10 这一档，S1 排在 S2 前面。
  5. 在订单簿里等待的订单，叫挂单方 Maker，它提供流动性。一到就成交的订单，叫吃单方 Taker，它消耗流动性。
  6. 打个比方，订单簿像菜市场的两排摊位。出价最好的人站最前面。管理员拿新顾客和对面第一位比价。
  7. 但这个比喻有一处不成立。菜市场可以讨价还价，撮合引擎不会。成交价永远取挂单方的价格。所以你挂 101 买，卖一价是 100，你会以 100 成交。多出的 1 不会白付。
02 · 撮合规则

价格优先，时间优先：FIFO

1价格更好的先成交
2同价先到的先成交
  1. 撮合的核心规则只有两条。第一，价格更好的先成交。买单越高越好，卖单越低越好。
  2. 第二，价格相同时，先到的先成交。这叫时间优先，也叫 FIFO，先进先出。
  3. 来看动画。现在来了一个新卖单 S6，价格 100.10，数量 0.5。它排到这一档的队尾，在 S2 后面。
  4. 这时一个买单要吃 1.0。引擎从队头开始取。S1 的 0.8 全部成交，S2 再成交 0.2。
  5. S6 的价格和 S1 一样，但它来得晚，一点都没轮到。这就是时间优先。想排在前面，要么出更好的价，要么来得更早。
  6. 如果有人挂 100.05 卖出，它的价格更好。不管来得多晚，它都排到最前面，成为新的卖一。
02 · 逐档吃单

限价买 100.20 × 2.5，引擎怎么配对

限价买 100.20 × 2.5 · 剩余 2.5
(2.0×100.10 + 0.5×100.20) ÷ 2.5
成交均价 = 100.12
循环：能成交吗 → 吃队头一个 → 扣减数量 → 还有剩余吗？
无剩余 → FILLED
  1. 现在看一笔完整的撮合。用户下了一个限价买单，价格 100.20，数量 2.5。
  2. 引擎先看卖一价 100.10。买价 100.20 不低于它，能成交。和队头 S1 成交 0.8，还剩 1.7。
  3. 继续，和 S2 成交 1.2，成交价还是 100.10。100.10 这一档被吃空，订单还剩 0.5。
  4. 卖一价变成 100.20。买价等于它，仍然能成交。和 S3 成交 0.5，订单全部成交。
  5. 算一下均价。2.0 个成交在 100.10，金额 200.20。0.5 个成交在 100.20，金额 50.10。合计 250.30，除以 2.5，得到 100.12。
  6. 注意前两笔的成交价是 100.10，不是用户出的 100.20。这就是开头的答案，成交价取 Maker 价格。
  7. 引擎每次只吃一个挂单，吃完回到开头再检查。没有剩余就结束，订单状态变成 FILLED。
03 · 订单类型

限价单与市价单

LIMIT 限价单
指定价格。能成交就成交，剩余挂单。
MARKET 市价单
不指定价格，逐档吃，直到吃够或吃空。
盘口越薄，吃穿的档位越多，滑点越大。
市价买 4.0 · 已成交 0.0 · 均价 —
  1. 先看最基础的两种订单。限价单指定价格。能成交的部分立即成交，剩下的挂进订单簿。立即成交的部分，它是 Taker。挂进去的部分，它就是 Maker。
  2. 市价单不指定价格。它没有限价，所以总能成交。它一档一档往上吃，直到吃够，或者对手盘被吃空。
  3. 举个示例，市价买 4.0。先吃完 100.10 这一档，一共 2.0。
  4. 还差 2.0，再吃 100.20 这一档。成交均价是 100.15，比屏幕上的卖一价贵了 0.05。
  5. 这个差距就是滑点。盘口越薄，市价单吃穿的档位越多，均价离屏幕价越远。如果对手盘被吃空还没买够，剩余部分会被取消，状态是 EXPIRED。想亲手体验，可以打开配套的深度与滑点实验页。
03 · 条件订单

止损限价单与 OCO 二选一

条件单服务 · 业界通用做法

止损卖 1.0
触发 99.50 · 限价 99.40

订单簿

还没有这笔订单

OCO · 腿 1

止盈 限价卖 101.00

OCO · 腿 2

止损 触发 99.50
币安：订单列表 · contingencyType=OCO
  1. 再看止损限价单。它带一个触发价和一个限价。示例，触发价 99.50，限价 99.40，卖出 1.0。
  2. 注意，触发之前，它不在订单簿里。业界通常由一个独立的条件单服务，盯着最新价。
  3. 最新价跌到 99.50，条件触发。系统这时才生成一个普通限价卖单，送进撮合。币安对应的类型叫 STOP_LOSS_LIMIT。
  4. OCO 是二选一订单。两个订单绑在一起。比如一个止盈限价卖单，加一个止损单。
  5. 只要其中一个成交，另一个自动撤销。币安把它做成订单列表，联动类型叫 OCO。币安的订单列表还支持 OTO 类型，这里不展开。
03 · 订单类型

冰山单与只做 Maker

冰山单 · icebergQty

卖 3.0 · 每次显示 1.0

Post-Only · LIMIT_MAKER

卖一价 100.10 · 买一价 100.00
挂买 100.10 →
挂买 100.05 →
做市商常用：Maker 手续费通常低于 Taker
  1. 冰山单是给大额订单用的。示例，挂卖 3.0，但每次只在订单簿里显示 1.0。
  2. 别人从深度里只能看到 1.0。拆分份数等于总量除以显示量，向上取整，这里是 3 份。
  3. 显示的部分成交以后，系统补上下一份。份数上限由 ICEBERG_PARTS 过滤器限制。这样，大单不会一下子全部暴露在深度里。
  4. 再看 Post-Only，币安的订单类型叫 LIMIT_MAKER。它保证这笔订单只当挂单方。
  5. 示例，卖一价 100.10，你用 Post-Only 挂 100.10 买入。这单会立刻成交，所以系统直接拒绝它。
  6. 改成挂 100.05 买入，就不会立刻成交，它进订单簿排队。做市商常用它，因为 Maker 手续费通常更低。费率的细节，第 11 集会讲。
04 · 有效方式 Time In Force

同一本订单簿，同一笔订单，试三遍

限价买 100.10 × 3.0 · 100.10 以内可吃 2.0，差 1.0
  1. 下单时还要选有效方式，也就是 TIF。它决定没成交的部分怎么处理。我们拿同一本订单簿试三遍。
  2. 订单是限价买 100.10，数量 3.0。卖盘在 100.10 只有 2.0，所以最多成交 2.0，还差 1.0。
  3. 第一遍用 GTC。2.0 立即成交，剩下的 1.0 挂进买盘，成为新的买一。它会一直挂着，直到成交或撤单。
  4. 第二遍用 IOC。同样成交 2.0，但剩下的 1.0 立即取消。订单最终状态是 EXPIRED。
  5. 第三遍用 FOK。引擎先预演，累加 100.10 以内能吃的量。只有 2.0，不够 3.0。
  6. 于是整单取消，一笔也不成交，订单簿完全没被改动。FOK 要么全部成交，要么什么都不发生。实现上，关键就是先算总量，再决定动不动订单簿。
05 · 订单生命周期

订单状态机：只能向前走

  1. 订单从进入系统到结束，会经过一组状态。先看最短的一条路。校验没通过，比如价格不符合 tickSize，直接 REJECTED。
  2. 引擎接受订单，状态是 NEW。部分成交以后，变成 PARTIALLY_FILLED。剩余也成交了，就是 FILLED。
  3. 用户撤单，走向 CANCELED。IOC 或 FOK 没能成交的部分被系统取消，走向 EXPIRED。
  4. 终态一共四个，FILLED、CANCELED、REJECTED、EXPIRED。订单进入终态，就不再变化。REJECTED 表示订单根本没进入撮合。EXPIRED 表示订单按规则被系统取消。
  5. 币安还定义了 EXPIRED_IN_MATCH，表示订单因为自成交预防被取消。下一集细讲。
  6. 状态只能往前走。假设下游先收到 FILLED，后来又收到一条旧的部分成交消息。这时必须按序号丢掉它。
常见误区

三个误区

✗ 挂高价买会多付钱 → 成交价取 Maker 价格，多出的不会白付
✗ 撤单立即生效 → 撤单也要排队定序
✗ 市价单按最新价成交 → 薄盘口会吃穿多档，热门币上线时尤其明显
  1. 最后看三个常见误区。第一个，挂高价买会多付钱。不会，成交价取 Maker 价格，多出的部分不会白付。
  2. 第二个，撤单立即生效。也不对。撤单指令同样要排队，同样要分配序号。
  3. 看这个队列。序号 41 是别人的吃单，序号 42 才是你的撤单。引擎先处理 41，你的挂单已经成交了。所以撤单要预留时间，别指望最后一刻撤掉。
  4. 第三个，市价单按最新价成交。在薄盘口里，市价单会吃穿多个档位。热门币刚上线时尤其明显。业界常见的缓解办法，是上线初期只开放限价单，暂停市价单。
本集小结

记住三件事

  • 订单簿按价格档组织，价格优先、时间优先，成交价取 Maker 价格。
  • 订单类型决定怎么进场；TIF 决定没成交的部分去哪。
  • 状态只能向前走，终态有四个，下游按序号处理消息。
