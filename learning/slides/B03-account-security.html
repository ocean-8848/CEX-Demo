① 信息泄露泄露、钓鱼、木马
② 获取凭证撞库、钓鱼站、SIM

⑤ 加地址攻击者提币地址

支线 A：从 ③ 登录 → 盗用 API Key 刷单，帮攻击者拉盘出货
支线 B：从 ① 泄露 → 冒充客服，诱导用户自己转账
  1. 打个比方。盗号像小偷进小区偷保险箱。他先拿到门禁卡，再骗过保安。然后换掉你家门锁，改掉你的快递地址，最后把东西寄走。
  2. 对应到交易所。第一步信息泄露，比如数据库泄露、钓鱼、木马。第二步获取凭证，比如撞库、钓鱼站、SIM 卡劫持。第三步，登录账户。
  3. 第四步，修改安全设置。改 2FA、改邮箱、关反钓鱼码。这是最强的信号。正常用户很少在新设备登录后，马上改 2FA。
  4. 第五步，加入攻击者的提币地址。第六步，发起提币。好的物业把最严的检查放在寄走东西这一步，而不是小区门口。
  5. 还有两条支线绕开了提币。一条是盗用 API Key 刷单，帮攻击者拉盘出货。一条是冒充客服，诱导用户自己转账。所以只守提币不够。

  1. 第二步的具体手法，我们叫攻击剧本。钓鱼站拿到密码，还能实时转发 2FA 码，绕过 TOTP。最有效的是 Passkey 和反钓鱼码。撞库用的是别处泄露的同一密码，靠新设备二次验证和风险评分。
  2. SIM 卡劫持，把你的手机号转到攻击者的卡上，短信验证码就失守了。所以短信不能做唯一因素。恶意浏览器插件偷走会话或 API Key，要靠 IP 白名单和权限分离。
  3. 客服冒充骗的是信任，绕过全部技术防线。地址投毒，是生成首尾相同的地址，再给你转一笔小额或零额。你从历史记录里复制，就复制到了攻击者的地址。
02 · 防线分层

越靠近资金出口，防线越严

① 识别：是不是本人反钓鱼码、Passkey漏：撞库、木马
② 登录风控设备指纹、IP 信誉、新设备二次验证漏：钓鱼站实时转发
③ 敏感操作改密或改 2FA 后冷却、行为评分漏：不改设置直接提
④ 资金出口新地址冷却、邮件确认、反诈弹窗漏：邮箱也被攻破
API Key 不走网页登录 → 限制加在 Key 本身：IP 白名单、权限分离
提币频率 ≪ 登录频率 → 出口处可以更严
  1. 第二段，防线分层，一共四层。第一层是识别，你是不是本人。反钓鱼码让用户认出假邮件。Passkey 让钓鱼站拿不到有效签名。它漏过撞库和木马，因为用户根本没访问钓鱼站。
  2. 第二层是登录风控。设备指纹、IP 信誉，新设备或异地登录要二次验证。它漏过钓鱼站实时转发的验证码。
  3. 第三层是敏感操作，第四层是资金出口。改密码、改 2FA 后的冷却期，新地址冷却，提币邮件确认，反诈弹窗。冷却期不阻止攻击者登录，它是在给真用户和风控争取时间。
  4. API Key 单独画出来。API 请求不走网页登录，限制必须加在 Key 本身。为什么越靠近出口越严？因为正常用户提币的频率，远低于登录。

  1. 来做个攻防实验。左上是 6 个攻击剧本，下面是防线开关，右边是正常用户的摩擦。现在一道防线都没开，6 个剧本全部得手。
  2. 打开设备指纹和新设备二次验证。撞库被拦住了。代价是换设备时多一步，大约 30 秒。
  3. 再打开 Passkey。它绑定网站域名，钓鱼站拿不到可用的签名。有意思的是，摩擦反而下降了。首次设置约 1 分钟，之后比输密码还快。
  4. 再加上改设置后的提币冷却。SIM 卡劫持改了手机号，也要等 24 到 48 小时才能提币。真用户有时间发现异常。代价是这段时间不能提币。
  5. 再给 API Key 加 IP 白名单。恶意插件偷到 Key，换一台服务器就用不了。开发者只需配置一次。
  6. 最后加上地址相似度提示和反诈弹窗。地址投毒会被提示出来。客服冒充却只能提醒，因为操作的是用户本人。技术防线不能代替用户做决定。
03 · 风险评分与挑战升级 · 分值和阈值均为示例

放行、挑战升级，还是拦截？

< 30 放行
30–69 挑战升级
≥ 70 拦截
  1. 第三段，风险评分。风险服务根据设备、IP、时间和操作类型，算出 0 到 100 的风险分。低于 30 放行，30 到 69 挑战升级，70 及以上拦截。这些数字都是示例。
  2. 示例甲。新设备登录，加 25 分。但他用的是已绑定的 Passkey，减 30 分。合计负 5 分，低于 30，直接放行。
  3. 示例乙。新设备加 25，IP 国家和历史不同再加 15，合计 40 分。进入中间档，系统要求补一次 Passkey 或邮件验证。通过后，再发一条安全通知。
  4. 示例丙。在乙的基础上，用了机房 IP，加 20。登录 10 分钟内就改安全设置，再加 30。合计 90 分，拦截并锁定敏感操作。
  5. 注意分工。风险服务只给分数，身份服务决定怎么挑战，两边能单独调阈值。中间档最关键，它把误杀变成了多一步验证。真实系统通常是规则加机器学习，新规则先跑影子模式。
04 · 敏感操作状态机

冷却期：能交易，不能提币

  1. 第四段，敏感操作状态机。账户平时处在正常状态。风险分进入中间档，就转到挑战状态。挑战通过回到正常，连续失败就锁定。
  2. 改密码、改 2FA、改邮箱或手机号，会进入冷却状态。冷却期里，用户可以登录、交易、充值，只是不能提币。这是体验和安全的折中。
  3. 风险分进入高档，或者用户自助冻结，账户直接锁定。锁定后只能走恢复流程，人工审核通过才回到正常。恢复必须比正常登录更严格。
  4. 攻击者最理想的路径，是改设置进入冷却，等冷却结束，再提币。所以冷却期越长，真用户越有机会发现异常。

⚠ 恢复不能只靠客服判断：社会工程擅长制造紧急感——“我的仓位马上要被强平”
  1. 再看账户恢复。用户丢了 2FA 或邮箱，要重新拿回账户。这个流程是攻击者最喜欢的后门。因为它的设计目的，就是在没有正常凭证时放行。
  2. 业界通用做法是这样的。提交申请后，先做活体人脸识别，和 KYC 照片比对。再查申请设备和 IP 的风险分。高风险申请由安全团队人工复核。
  3. 然后通知原邮箱和原手机号，有人在申请恢复你的账户。再等一段时间，示例是 48 小时，让原用户有机会拒绝。恢复完成后，还要限制提币一段时间。
  4. 注意，恢复绝不能只靠客服判断。社会工程攻击者擅长制造紧急感。比如，他会说自己的仓位马上要被强平了。

截至 2026 年公开资料：币安自 2023 年加入 FIDO 联盟，支持 Passkey 登录；时长以官网为准
  1. 第五段，规则表。先看公开事实。截至 2026 年公开资料，币安美国站帮助中心写明了两条。改密码后，24 小时不能提币。全球站有类似限制，时长以官网为准。重置 2FA 后，48 小时内禁止提币和 P2P 卖出。
  2. 下面是业界通用做法。白名单新增地址，示例是 24 小时内不能向它提币。新设备登录不满 24 小时就提币，要挑战升级加人工审核。
  3. 开启 API Key 的提币权限，必须绑定 IP 白名单。这是币安 API 管理页的公开要求。目标地址和历史地址首尾相同、中间不同，就弹出投毒警告。
  4. 另外，根据同一时点的公开资料，币安自 2023 年起加入 FIDO 联盟。它支持 Passkey 登录。

撞库开始时，曲线会先告诉你

指标告警条件 · 示例含义

  1. 防线还要有监控。登录失败率 5 分钟内上升 3 倍，说明撞库开始了。同一个 IP 1 小时尝试超过 50 个账户，就是撞库来源。安全设置修改量到了基线的 5 倍，可能是钓鱼潮或数据泄露。
  2. 挑战通过率突然下降，要么误杀上升，要么攻击者在试探。恢复申请量是基线的 3 倍，有人在攻击恢复流程。用户自助冻结突然变多，说明用户发现了异常。
  3. 最后一个指标方向相反，正常用户的摩擦分。季度上升超过 20%，说明防线过严，用户可能流失。这些阈值都是示例。

  1. 来看真实案例。据公开报道，2018 年 3 月，攻击者用仿冒域名钓鱼。他们收集了大量币安用户的凭证。
  2. 攻击者为这些账户创建交易 API Key。然后用被盗账户高价买入 VIA，同时用自己预先充值的账户卖出。
  3. 注意，这条链上没有一笔从被盗账户提币。价值通过交易，从受害者转给了攻击者。只守提币的风控会漏掉它。

  6. 再看 2019 年 5 月。攻击者拿到大量用户的 API Key、2FA 码等数据。一次提走约 7000 BTC。那次没能在提币前拦住，由 SAFU 覆盖。两个案例的入口都是用户凭证。
06 · 局限与权衡

防线越多，正常用户越烦

场景偏安全偏体验平衡建议
登录每次都要 2FA已知设备免 2FA已知设备 + 低风险免验证
提币每笔邮件确认白名单免确认白名单小额免，大额确认
改设置冷却 72 小时不冷却24–48 小时，可交易不可提
API Key永不给提币权限自由开启开启必须绑 IP 白名单
恢复账户全人工，耗时一周邮件即可恢复活体 + 原渠道通知 + 等待期

误杀 False Positive

正常用户被拦 → 投诉、流失
提币：宁可多误杀

漏放 False Negative

攻击者被放行 → 资产损失、赔付
登录：可多容忍漏放，后面还有防线
最好的防线同时提升安全和体验：Passkey 防钓鱼，登录也更快
防不住的部分：客服冒充让用户自己操作 → 反诈弹窗、官方验证渠道、用户教育
  1. 第六段，权衡。每道防线都有成本。登录，已知设备加低风险分可以免验证。提币，白名单地址小额免确认，大额要确认。改设置，冷却 24 到 48 小时，期间可以交易，不能提币。
  2. API Key 可以开提币权限，但必须绑 IP 白名单。账户恢复，用活体识别加原渠道通知加等待期，而不是一周的全人工。
  3. 再看误杀和漏放。平台通常对提币容忍更多误杀，对登录容忍更多漏放。因为登录被漏放，后面还有防线。提币被漏放，就没有了。
  4. 最好的防线，同时提升安全和体验，Passkey 就是例子。防不住的部分是客服冒充，只能靠反诈弹窗、官方验证渠道和用户教育。
本集小结

记住三件事

  • 攻击者要走完整条链，平台拦住一步就够；支线让只守提币不够。
  • 风险评分三档：放行、挑战升级、拦截；中间档把误杀变成多一步。
  • 冷却期和恢复流程为真用户争取时间；越靠近出口越严。
