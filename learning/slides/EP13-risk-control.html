风控：交易所的安检系统

所有乘客过探测门 · 门响了手检 · 监控室回看录像

比喻

拦或放，两种结果

真实风控

五种动作 · 微秒级决策 · 误杀与漏放的权衡
  1. 假设你凌晨三点登录交易所，想把全部余额提走。页面却提示，这笔提币需要人工审核。你可能会很生气。可从交易所的角度看，它正在判断，你到底是不是本人。
  2. 这一集我们讲风控。风控就像机场安检。所有乘客都要过金属探测门。门响了，安检员再手检。门后面还有监控室，回看录像找可疑的人。
  3. 不过比喻只能帮你入门。安检好像只有拦和放两种结果，真实的风控有五种动作。它还要在极短的时间里做决定，并且在误杀和漏放之间取舍。

五种动作：通过拒绝限制加验证转人工
目标：①减少资金损失 ②满足合规 ③降低正常用户摩擦　—— ③ 与 ①② 互相冲突
  1. 交易所同时面对四类风险，每类对应一层风控。第一层是交易前。它防余额不足下单、胖手指错价，还有请求洪水。
  2. 第二层是交易中，也叫市场监察。它找自成交、刷量、幌骗和拉盘砸盘。
  3. 第三层是资金，主要是提币。它防盗号提币、洗钱，以及向制裁地址转账。
  4. 第四层是账户。它防撞库登录、SIM卡劫持，以及钓鱼之后改密码。
  5. 注意，风控不等于拒绝。风控有五种动作：通过、拒绝、限制、加验证、转人工审核。比如降额度，就是一种限制。
  6. 风控的目标有三个：减少资金损失，满足合规，降低正常用户的摩擦。第三条和前两条互相冲突。风控所有的难点，都来自这个冲突。

  1. 先看交易前风控。订单进入撮合引擎之前，要过五道检查。它是同步的，必须快。业界通常把延迟预算压在1毫秒以内，这是示例数字。
  2. 第一道，校验格式。价格精度、数量精度、最小名义价值，都要符合交易对的规则。
  3. 第二道，价格保护带。订单价格不能偏离参考价太远。下一个画面我们专门算一算。
  4. 第三道和第四道，检查最大订单和挂单数量。单笔不能太大，一个账户的未成交订单也不能太多。
  5. 最后一道，检查可用余额。余额足够，系统就冻结对应金额。五道都通过，订单才进入撮合。
Percent Price Filter

价格保护带：拦住胖手指

币安现货过滤器：PERCENT_PRICE · PERCENT_PRICE_BY_SIDE
由 exchangeInfo 下发 · 参考价参数 avgPriceMins
  1. 价格保护带怎么算？举个示例。参考价是50000 USDT，上限是5%。买单价格高于参考价的1.05倍，也就是52500，系统就拒绝。
  2. 一笔买单报价52000，偏离4%，在带内，系统通过。
  3. 再来一笔买单，报价60000，偏离20%，系统直接拒绝。手滑填错的价格，根本进不了撮合。这就是防胖手指。
  4. 注意参考价从哪里来。根据币安公开资料，现货用一段时间的加权平均价做参考价。相关过滤器在 exchangeInfo 接口里下发，具体倍数以接口返回为准。
  5. 为什么不用最新成交价？看这根线。一笔小单就能把最新价打到58000。如果拿它当参考价，保护带会跟着被拉歪。平均价几乎不动。合约里的标记价格，用的也是这个思路。
Market Surveillance

交易中风控：市场监察找四类行为

行为定义识别信号 · 业界通用
自成交同一用户的买单和卖单互相成交双方用户 ID 相同
刷量关联账户对敲，制造虚假成交量设备、IP、资金来源关联

刷量 · 幌骗 · 异步看一段时间的行为才能判断事后发现 → 案件系统
  1. 第二层，交易中风控，也叫市场监察。它找四类行为。自成交，是同一用户的买单和卖单互相成交。刷量，是关联账户之间对敲，制造虚假成交量。
  2. 幌骗，是挂大单制造假象，快成交时撤单。拉盘砸盘，是在低流动性的币上集中拉高，然后抛售。
  3. 自成交有同步解法，叫自成交预防，简称 STP。根据币安公开资料，下单时可以指定 STP 模式。撮合引擎发现两边是同一账户，就让一边或两边订单失效。
  4. 刷量和幌骗没有同步解法。系统必须看一段时间的行为才能判断。所以它们属于异步风控，事后发现，再送进案件系统。

KYT 标签：暗网市场 · 混币器 · 被盗资金 · 制裁实体　→　充值命中：冻结转合规　提币命中：拒绝
  1. 第三层和第四层要放在一起看。盗号者拿到密码以后，典型路径有四步。登录，改2FA或邮箱，加新提币地址，然后提走全部余额。
  2. 账户风控在第一步设卡。新设备、机房 IP、异地 IP，都是信号。但正常用户也会换手机。所以账户风控输出风险分，不是是或否。
  3. 第二步改安全设置，会触发冷却期。根据币安公开资料，修改安全设置后会暂停提币24小时，具体时长以官网为准。
  4. 第三步加新地址。首次向一个地址提币，系统可以加验证，或者延迟处理。提币地址白名单也是在防这一步。
  5. 第四步提币。这是资产离开交易所的唯一出口，链上转账不可撤回，所以这一层最严。单笔限额、24小时累计、黑名单、KYT 评分，都放在这里。
  6. KYT 是链上交易监测。服务商给地址打标签，比如混币器、被盗资金、制裁实体。充值方向命中，就冻结并转合规审核。提币方向命中，就直接拒绝。

  1. 现在把各层串起来，看一个风控事件怎样被决策。业界通常用三件套：规则引擎、评分模型、人工审核。
  2. 第一关是硬规则，比如黑名单、制裁、冷却期。硬规则便宜，可解释，零容忍。示例中这笔提币的目标是制裁地址，直接拒绝，不进模型。
  3. 没命中硬规则，就计算特征。模型把几十个弱信号，合成一个0到100的风险分。举个示例，这笔分数是18，低于30，直接通过。
  4. 另一笔分数是52，落在30到70之间。系统要求加验证，比如2FA或邮件确认。加验证是一种软拒绝，它把误杀的成本，转成用户的一次点击。
  5. 再一笔分数是85，高于70，进入人工审核队列。审核员可以放行，可以拒绝，也可以冻结账户并联系用户。
  6. 最后，所有决策都要记录，连同当时的特征快照。审核员的结论，就是模型的训练标签。没有记录，模型就无法改进。
Latency Budget

延迟预算：同步路径只放便宜的检查

  1. 每个风控检查都消耗时间。请求路径上的时间有上限，这个上限叫延迟预算。横轴是对数刻度，下面的数字都是示例。
  2. 下单的预算不到1毫秒。只能做内存里的检查：余额、价格带、限频计数。调用外部 KYT，或者跑大模型，都来不及。
  3. 登录宽一些，大约100到300毫秒。可以查设备指纹和 IP 信誉，再跑一个轻量模型。
  4. 提币可以是秒级到小时级。KYT、复杂模型、人工审核都能用上。链上不可撤回，多等几分钟换安全，是值得的。
  5. 市场监察是异步的，分钟级到天级。客户端拿到下单回执时，它还没开始。等它发现问题，成交早已发生，只能限制账户、冻结资金、追责。
Token Bucket

令牌桶：允许突发，限制长期速率

容量 B · 示例
10
补充速率 R · 示例
2 / 秒
每个请求权重 N · 示例
2
  1. 网关上最便宜的检查是限流。业界常用令牌桶来讲原理。一个桶最多装B个令牌，系统按速率R往桶里加。示例中，B是10，R是每秒2个。
  2. 每个请求要取走N个令牌，N就是请求的权重。示例中权重是2。来一个请求，桶里剩8个。
  3. 令牌桶允许突发。客户端一口气发了5个请求，正好把10个令牌用光。
  4. 第6个请求来了，桶里一个令牌也没有。系统拒绝请求，返回 HTTP 429。
  5. 等3秒，按每秒2个补回6个令牌，又能发3个请求。长期来看，平均速率被R锁住，突发大小被B锁住。
  6. 你可以把它想成一个匀速滴水的杯子，满了就溢出。但比喻不等于实现。币安文档没有说明内部用令牌桶还是固定窗口，令牌桶只是业界通用的解释方式。

  1. 现在对照币安的公开规则。根据币安 API 文档，每个接口有一个权重。重的接口，比如一次查询全部交易对，权重就高。
  2. 限额按 IP 计算，不按 API Key 计算。每个响应都带一个已用权重的响应头，客户端随时能看到自己用了多少。下单还有独立的订单数限制。
  3. 已用权重超过限额，接口返回429。响应带一个 Retry-After 头，告诉你要等多久。
  4. 收到429还继续请求，IP 会被自动封禁，接口返回418。
  5. 封禁时长按违规历史递增，从2分钟到3天。注意封的是 IP，同一 IP 下的全部程序都会受影响。
  6. 所以客户端要读响应头控制节奏。收到429立刻停下，按 Retry-After 等待。

  1. 风控本质上是一个分类问题。每个事件有真实标签，好人或坏人，也有风控决策，拦或放。拦了好人，叫误杀。放了坏人，叫漏放。
  2. 来看一组示例数据。横轴是风险分，绿色是1000个好人，红色是100个坏人，两堆有重叠。阈值放在70，分数达到70就拦。误杀率3.5%，漏放率却有40%。
  3. 把阈值收紧到50。漏放率降到18%，误杀率涨到12%。
  4. 再收紧到30。漏放只剩5%，可误杀涨到32%。差不多三个好人里，就有一个被拦。
  5. 同一个阈值，同时影响误杀和漏放，两者不能同时降到零。人工审核是缓冲区，但容量有限。正常用户等6小时才提到币，体验和被误杀差不多。
  6. 所以阈值是商业决策：一次漏放的损失，对比一次误杀的损失乘以误杀次数。业界通常让新规则先跑影子模式，只记录不拦截，确认误杀率再上线。

误区：攻击者会一次提大额

实际会探测阈值，拆成多笔小额
→ 24h 累计限额，按账户和设备两个维度
  1. 最后看两个必须硬起来的地方。第一是制裁合规。主要名单有美国财政部 OFAC 的 SDN 名单，还有联合国、欧盟、英国的名单。
  2. 制裁检查在三处执行。注册和 KYC 时，筛查姓名、国籍和居住地。登录时，筛查 IP 地理位置。充值和提币时，筛查链上地址。
  3. 制裁命中是硬规则，直接拒绝并上报合规团队，不能交给模型打分后放行。公开报道显示，2023年币安与美国监管和解，同意支付约43亿美元。合规不是可选功能。
  4. 第二是故障时的选择。风控服务宕机了，是放行还是拒绝？资金相关的检查，一律失败即关闭，也就是故障时拒绝。KYT 服务商超时，就转人工，不能默认放行。
  5. 再说一个常见误区，以为攻击者会一次提走大额。实际上，攻击者会探测阈值，把提币拆成多笔小额。所以要加24小时累计限额，并且按账户和设备两个维度累计。
Summary

记住三件事

  • 四层风控：交易前、资金是同步的，交易中监察是异步的。
  • 硬规则零容忍，模型管灰色地带，人工兜底；429 要停，否则 418。
  • 误杀与漏放此消彼长，阈值是商业决策。
