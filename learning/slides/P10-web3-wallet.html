  1. 先把三种托管模式摆在一起。交易所托管，签名由交易所控制，资产记在交易所账本上。站内转账不上链，平台也能冻结。
  2. 传统自托管钱包，用户独自控制签名，靠12个或24个单词的助记词恢复。资产在链上地址，平台冻结不了。
  3. MPC 无私钥钱包在中间。资产同样在链上地址，也没有助记词。签名需要用户设备加币安，或者用户设备加云备份。
  4. 注意最后一行。平台不能单独冻结链上资产，但它可以停止参与签名。不能单独动钱，不等于永远可用。
MPC · Threshold Signature

三片密钥，任意两片才能签名

  1. 先看 MPC 无私钥钱包。打个比方，它像一个保险柜，需要3把钥匙里任意2把才能打开。一把在你手机里，一把在币安，一把加密后放在你自己的云盘里。
  2. 根据币安公开资料，创建钱包时生成3个密钥分片。分片1由币安保管，分片2存在用户设备上。分片3用你设置的恢复密码加密，备份到个人云盘。
  3. 但比喻在这里不成立。保险柜的钥匙真实存在，而 MPC 里完整私钥从不出现。业界通常这样做：三方各自生成随机数，共同算出公钥和地址。
  4. 签名时，设备分片和币安分片各算一部分，合成一个完整签名。这叫门限签名，3片里任意2片就能签。
  5. 反过来，币安只持有1片，无法单独动用户资产。这是币安官方文章的说法。
  6. 丢了手机怎么办？新设备登录，输入恢复密码。云备份分片加币安分片，重新生成新的分片。地址不变，旧设备上的分片作废。
State Machine · 业界通用 MPC 做法

钱包的一生：最危险的是没备份

  1. 把钱包的一生画成状态机。用户创建钱包，三方完成分布式密钥生成，钱包进入已激活但未备份的状态。注意，这是危险状态。此时只有两片可用，丢一片就无法签名。
  2. 用户完成云备份，钱包才进入正常的已激活状态。币安还提供快速备份，用生物识别代替恢复密码，加密分片交给第三方安全服务商保存。
  3. 正常使用时，用户发起交易，设备分片和币安分片联合签名，完成后回到已激活。
  4. 换机或丢失手机，进入恢复流程。恢复不是把私钥找回来，而是重新分片。说明一下，这是业界通用的 MPC 做法，币安具体协议没有完整公开。
  5. 最危险的路径在这里。没备份就丢了设备，钱包永久无法签名。另外，根据新闻报道，2025年12月起，一个币安账户最多可创建5个无私钥钱包。
Money Flow · CEX ↔ Web3 Wallet

每一次移动，都是真实的链上交易

  1. 现在看资金流。从交易所转进钱包，第一步是账本扣减，这是内部操作。第二步，币安热钱包签名，把币转到你的钱包地址。这就是一次完整的提币。
  2. 币到了钱包地址，币安账本就不再记录这笔资产。币安的储备金证明，也不再包含它。
  3. 第三步，你在钱包里用 DEX、链上赚币或者跨链桥。每一次都是你签名的链上交易，要付 gas，结果不可撤销。
  4. 反方向，从钱包转回交易所，是一次完整的充值，要等确认数达标才入账。App 把两边做成一键划转，但底层仍是链上交易。部分 gas 可能由平台补贴，以官网为准。
Call Chain · 签名前先模拟

一次签名：先模拟，再提示，再联合签名

  1. 一次签名，系统内部怎么走？App 先在本地构造交易，把交易摘要发给网关，请求联合签名。网关鉴权后，转给持有币安分片的钱包签名服务。
  2. 签名服务先不签。它把交易交给模拟服务试运行，解析资产变化。示例结果是：将转出100 USDT，授权额度为无限。风控服务再检查目标地址和合约的风险标签。
  3. 风险提示返回 App。用户阅读提示，确认之后，才开始真正的签名。
  4. MPC 签名要来回两轮。App 合成完整签名，再广播到区块链节点。交易一旦广播，任何一方都无法撤回。
  5. 注意这里的两面性。币安分片参与签名，所以币安能在签名前做风控，这是相对助记词钱包的优势。但同一个机制也意味着，币安可以拒绝签名。签名服务和模拟服务，是按业界通用做法画出的组件。
DEX Aggregator

链下算路由，链上执行，合约检查最低到手

  1. 接下来是钱包里的 DEX 兑换。用户选择从 USDT 兑换到代币 X。界面显示预估数量、最低到手数量、滑点容忍度和网络费。
  2. 背后是 DEX 聚合器。它同时查询多个去中心化交易所，把一笔订单拆到多个池子。示例里，1000 USDT 的60%直接走池子 A。另外40%先换成 BNB，再换成 X。
  3. 路由是链下算、链上执行。聚合服务把路径写进交易数据，由用户签名执行。最低到手数量也写在交易里，由合约检查。这才是滑点保护真正执行的地方。
  4. 出错点在时间差。链下报价和链上执行之间，行情可能已经变了。到手数量低于最低值，交易就会失败。失败也要付 gas。
MEV · Sandwich Attack

三明治攻击：机器人夹住你的买单

  1. 用户把兑换交易广播到公开内存池。买入代币 X，滑点容忍度2%。问题是，内存池是公开的，三明治机器人也在看。
  2. 机器人抢先买入 X，把价格推高。用户的买单接着以更差的价格成交。机器人再把 X 卖掉，赚走用户推高的那段差价。这就是三明治攻击。
  3. 机器人能抽走多少，取决于你的滑点容忍度。设成2%，就是最多2%的潜在损失。容忍度越大，机器人的利润越多。
  4. 防御方法是私有交易通道。交易不进公开内存池，直接交给出块者。根据公开资料，币安钱包宣称提供 MEV 保护。局限是，你要信任通道运营方和出块者，而且不是所有链都有成熟的私有通道。
Bridge · On-chain Earn

跨链桥：锁定一边，铸造另一边

  1. 再看跨链桥。常见做法是，在链 A 锁定资产，在链 B 铸造等量的包装资产。链 B 上的包装资产，靠链 A 的锁仓来支撑。
  2. 风险在验证环节。验证者私钥被盗，或者验证逻辑有漏洞，攻击者就能伪造证明。他在链 B 凭空铸币。公开案例发生在2022年10月。BNB Chain 的跨链桥 BSC Token Hub 被利用。攻击者凭空铸造了约200万枚 BNB。验证者随后暂停了链。
  3. 对比一下，交易所内部的跨链不需要桥。你在 BSC 充值 USDT，在以太坊提 USDT。交易所用两条链上各自的热钱包库存完成，风险由交易所的库存管理承担。
  4. 链上赚币也要区分清楚。交易所理财的资产留在币安账本内，由币安负责兑付。钱包里的链上赚币，资产在第三方协议合约里，由合约代码负责兑付。

Approval Phishing

一次签名，变成永久权限

  1. 最后一个风险，也是钱包用户最常遇到的。ERC-20 代币有一个 approve 操作。它允许某个合约，从你的地址转走若干代币。很多 DApp 默认请求最大整数，也就是无限授权。
  2. 用户访问了一个假冒网站，签了一个无限授权。授权本身不转钱，余额一分没少。所以签名的时候，用户几乎没有警惕。
  3. 链上从此多了一条记录：攻击合约可以转走你全部的 USDT。攻击者不急，他在等。几个月后，你充值了5000 USDT。攻击者调用 transferFrom，一次转走全部余额。
  4. 防御有三条。只授权本次需要的数量。定期撤销不用的授权，也就是把额度设为0。钱包在签名前模拟交易，显示风险。同类风险还有 permit 离线签名。NFT 也有 setApprovalForAll。

失败 1 · 以为有 SAFU 保护

SAFU 为交易所托管资产设计 · 钱包被钓鱼，平台通常无赔付义务 · 以官网条款为准

失败 2 · 换机未备份

旧手机已重置 · 无法恢复 · 资产永久锁死
  1. 把风险汇总一下。设备被恶意软件控制，币安分片服务中断。云盘被盗加恢复密码泄露，还有合约漏洞。这四类都由用户承担。平台承担的，主要是声誉和监管风险。
  2. 第一个失败场景。用户以为钱包余额受交易所保护。但用户保护基金 SAFU 是为交易所托管资产设计的。钱包资产在链上，被钓鱼转走后，平台通常没有赔付义务。这是业界通用规则，以官网条款为准。
  3. 第二个失败场景。用户换机前没有备份，旧手机已经重置。系统无法恢复，资产永久锁死。
Summary

记住三件事

  • 交易所账户是账本数字，钱包是链上地址；之间每次移动都是真实充提。
  • MPC：3 片任意 2 片签名；币安 1 片，不能单独动钱，但能风控、能拒签。
  • 滑点、跨链桥、无限授权：链上风险由用户自己承担。
