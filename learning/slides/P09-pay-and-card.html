Money Flow · 在途账户为业界通用做法

Pay 本身从不碰链

  1. 先看资金流。个人转账只有一步，借 A，贷 B。两个账户在同一个账本里，没有链上交易，所以没有 gas。
  2. 商户付款要经过在途账户。示例，用户付100 USDT，费率1%，99进商户，1进平台手续费收入。在途账户让用户已付和商户已入账可以分开对账，这是业界做法。
  3. 商户还可以选择自动兑换成结算币种，走闪兑通道。
  4. 链上边界只出现在商户提币时，法币边界只出现在法币结算时，而且只在部分地区。Pay 本身从不碰链。
Order State Machine · 参考开发者文档

PAID 是唯一的“资金已动”分界点

  1. 商户订单的状态机。商户下单，状态是初始。用户扫码打开收银台，变成待支付。
  2. 用户确认，账本划转成功，变成已支付。这是唯一的资金已动分界点。在这之前，用户余额没变，失败只需关单。
  3. 商户关单是已取消，超过有效期是已过期。取消和过期都不产生分录，失败路径非常便宜。
  4. 已支付之后可以退款，部分退款可以多次，累计等于订单金额就是全额退款。系统必须校验累计退款不超过订单金额，否则平台自掏腰包。
  5. 剩余金额进入商户结算周期。注意，结算这个状态是本集为说明加入的示意。
Call Chain · pay-service 为业界通用拆分

两次幂等：下单一次，扣款一次

  1. 来看调用链。商户服务器经网关创建订单，带上商户订单号。Pay 服务按这个订单号幂等落库，返回预支付单号和二维码。
  2. 用户扫码确认，经过2FA或生物识别。Pay 服务先问风控，检查付款人限额和商户风险等级。
  3. 通过后写账本，借用户，贷商户和手续费，幂等键是预支付单号。账本成功之后才改成已支付。顺序反了，就会出现显示成功、却没扣款的错账。
  4. 最后用 Webhook 通知商户。Webhook 是异步的，收不到回调时，商户应主动查询订单，不能直接判定失败。
  5. 落到分录上。示例订单100 USDT，商户选择自动兑换，价差0.1%。商户收到的99 USDT 卖给平台做市账户，换回98.901个稳定币。
  6. 平台真正的价值不在这1 USDT。Pay 把资金留在账本内。每少一次提币，就少付一次 gas，少一次热钱包出金风险。
Risks · Failure Cases · 业界通用做法

站内转账：快，也危险

  1. Pay 的风险有四类。第一是洗钱通道，站内转账不上链，链上分析工具看不到。所以收付双方都要 KYC，再对转账关系做关联分析。
  2. 第二是账户盗用，盗号者用 Pay 秒转资金，比提币更快。对策是新设备或改密后限制额度。第三是商户欺诈，对策是企业认证、结算延迟和保证金。第四是汇率风险，平台用闪兑即时对冲。
  3. 再看两个故障。一是 Webhook 丢失。商户宕机10分钟，误判订单失败，让用户再付一次。对策是以查询结果为准，并按商户订单号拒绝重复下单。
  4. 二是退款超额。两个退款请求并发，各自读到剩余可退100，各退100。对策是在同一事务里锁订单行，或者用乐观锁版本号。
Gift Card · Prepaid Voucher

兑换码不携带资产，只携带提取权

  1. 第二个产品，礼品卡。用户从余额创建礼品卡，选币种和金额，生成一串兑换码，还可以加一串密码。收到码的人在 App 里输入，资产即时到账。
  2. 示例，创建时冻结100 USDT，另收1 USDT 手续费。根据币安开发者文档，2023年8月21日起，购买或创建礼品卡收1%手续费。兑换不收费，以官网为准。
  3. 兑换码在站外传递，微信、邮件、实体卡都行。但码本身不携带资产，只携带提取权。
  4. 兑换时，消耗冻结，把100 USDT 划给兑换者。另一种做法，是创建时就转入平台的礼品卡负债账户。区别在于未兑换的钱算谁的，这会影响储备金证明和会计处理。
State Machine · CAS · 业界通用做法

一张卡，只能兑换一次

  1. 礼品卡状态机的关键，是兑换中这个状态。两个人同时输入同一个兑换码，只有一个能把状态从可用改成兑换中。
  2. 调用链上，网关先按用户和 IP 限流。礼品卡服务计算兑换码的哈希去查卡，数据库只存哈希，不存明文。
  3. 然后用比较并交换，也就是 CAS，把可用改成兑换中。再写账本，幂等键是卡片 ID。缺了 CAS，两个并发请求都会划转，平台多付100。
  4. 平台收入等于创建金额乘以费率。示例，某月创建100万 USDT，收入1万。月末还有20万没兑换，留在账本内，这就是沉淀资金。
  5. 风险也很典型。兑换码泄露就等于资金被盗，平台无法追回。诈骗者常要求受害者用礼品卡付款。另外，批量创建的 API 只对通过企业认证的机构开放。
Binance Card · 地区变化频繁，以官网为准

一张借记卡，命脉在合作方

  1. 第三个产品，Binance Card，一张借记卡。在受理该卡组织的商户刷卡，系统从资金账户实时卖币付款。发卡行是持牌机构，交易所本身不发卡。
  2. 它的地区变化很频繁。据新闻报道，2023年1月，币安与 Mastercard 在巴西推出卡产品。同年9月前后，Mastercard 结束了拉美和巴林的合作。
  3. 2023年12月20日，币安在欧洲经济区停止 Visa 借记卡服务。2025年10月起，币安在巴西重新上线 Mastercard 卡。
  4. 返现和费用来自多个第三方来源。欧洲版历史上按 BNB 月均持仓分7档，从0.1%到8%。巴西版最高2%，每月上限120雷亚尔。刷卡兑换法币收0.9%费用，以 App 内披露为准。
Authorization → Clearing · 示例

第一阶段：授权，同步、强实时

  1. 刷卡分两个阶段，先授权，后清算。商户 POS 发出50欧元授权请求，经卡组织转到发卡处理商。发卡处理商再回调币安的卡服务。卡组织通常要求数百毫秒内响应。
  2. 卡服务先问风控，检查卡状态、商户类别、地区和限额。再向报价服务要 BTC 兑欧元报价，示例1个 BTC 等于6万欧元。
  3. 接着冻结0.00084083个 BTC，已经含0.9%兑换费。冻结成功，批准消息一路返回，收银台显示成功。
  4. 1到3天后，清算消息到达。卡服务消耗冻结，记卖币和法币应付的分录。授权是同步的，清算是异步的，要和授权记录逐笔对账。
  5. 注意边界。币从不上链，BTC 在币安账本内被卖掉。法币边界在平台兑换账户到发卡行这一步，走银行转账。发卡行通常要求平台预存法币，否则授权会因余额不足失败。
Auth ≠ Clearing · Failure Cases

授权金额 ≠ 清算金额

  1. 授权金额和清算金额可以不同。酒店预授权200欧元，退房清算160欧元。加油站预授权1欧元，实际清算60欧元。
  2. 差额是平台的问题。如果授权时已卖出200欧元等值的 BTC，清算160后要退40欧元。退欧元还是买回 BTC，汇率风险由谁承担，取决于产品规则。
  3. 退货通常以法币或稳定币退回，不按原 BTC 数量退，用户承担期间的价格变化。
  4. 三个失败场景。2023年合作方退出，卡在多个地区下线。报价服务延迟2秒，卡组织判超时拒绝。清算比授权多出3欧元，用户余额又不足，平台只能先垫付再追收。
Unit Economics · 全部为示例

刷一次 50 欧元，平台赚多少

  1. 最后算一笔单笔账，全部是示例。消费50欧元，用户付出50除以6万，再乘以1.009。约等于0.00084083个 BTC。
  2. 平台兑换费收入0.45欧元。交换费是收单行付给发卡行的费用，欧盟借记卡上限0.2%。按50%分成，平台拿0.05欧元。
  3. 返现按1%算，支出0.5欧元。发卡与卡组织成本约0.1欧元。
  4. 单笔净收入是负0.1欧元。高返现会让卡业务亏损。平台用卡获客、锁定 BNB 持仓，而不是靠卡本身赚钱。
Summary

记住三件事

  • Pay 是划转，礼品卡是冻结 → 消耗 → 划转：只改账本，不上链。
  • 卡要走出交易所：授权同步冻结并卖币，清算异步结算，金额可以不同。
  • 平台的钱不全靠手续费：资金留存、沉淀资金、BNB 锁定。
