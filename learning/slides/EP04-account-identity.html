01 · 登录与会话 业界通用做法

✗ 快哈希 / 明文

MD5 · SHA-256 · 明文

设备与 IP
异常？二次验证

  1. 先看注册。用户提交邮箱或手机号，用验证码确认，再设置密码。业界通常只保存密码的慢哈希，并且加盐。例如 Argon2 或 bcrypt。
  2. 绝不能存明文，也不能用 MD5 这类快哈希。快哈希算得太快，数据库一旦泄露，很快就被暴力破解。
  3. 再看登录。系统先校验密码哈希，然后检查设备指纹和登录 IP。如果设备或地点异常，就要求二次验证。
  4. 开启了 2FA 的用户，还要输入动态验证码。全部通过以后，系统才签发会话凭证。
01 · 登录与会话

会话凭证：可吊销 vs 免查库

形态原理优点缺点
不透明令牌随机字符串，服务端查库得知归属可立即吊销每次都查存储
JWT带签名的 JSON，验签即读出用户 ID不查库，快签发后难作废

访问令牌 示例 15 分钟

有效期短，泄露窗口小

刷新令牌 服务端可吊销

改密码、退出所有设备 → 全部吊销
JWT 只是 Base64 编码，不是加密：任何人都能解码读到内容。
  1. 登录以后，系统给浏览器一个会话凭证。之后的请求带上它，就不用再输密码。凭证常见有两种形态。
  2. 第一种是不透明令牌，一个随机字符串，服务端查库才知道它属于谁。好处是能立即吊销，代价是每次都要查存储。
  3. 第二种是 JWT，一段带签名的 JSON。服务端验签就能读出用户 ID，很快。缺点是签发以后，很难提前作废。
  4. 业界通常组合使用。访问令牌有效期短，示例是 15 分钟。刷新令牌存在服务端，改密码或退出所有设备时，全部吊销。
  5. 还有一个常见误区。JWT 的内容只是 Base64 编码，不是加密。任何人都能解码看到，所以不要在里面放敏感信息。

  1. 现在看 2FA。它在密码之外，再验证一个你拥有的东西，也就是验证器。最常见的是 TOTP。绑定时，服务端生成随机密钥，做成二维码，用户扫码保存。
  2. 之后双方各自计算。来算一个示例。当前时间是 1700000017 秒。除以 30 向下取整，得到 56666667。这就是时间窗编号，每 30 秒加 1。
  3. 双方用 HMAC-SHA1 处理密钥和窗口编号，截取 6 位数字。示例是 492039。输入相同，结果就相同。
  4. 注意，网络上只传这 6 位数，密钥从不传输。服务端通常还允许前后各 1 个时间窗，容忍手机时钟误差。
  5. TOTP 也有弱点。数据库泄露，密钥也跟着泄露，所以要加密存储。短信验证码更弱，攻击者可以补办你的手机卡截获短信。这叫 SIM 卡劫持。

Header：API Key ✓　参数：…&signature ✓　Secret：✗ 不在请求里
网关：按 Key 查 Secret → 重算 → 常量时间比较
  1. 程序化交易要用 API Key。它分两部分。API Key 是公开标识，随请求明文发送。Secret Key 是签名密钥，永远不发送。
  2. 来看币安现货接口怎么签名。客户端先把参数拼成一个字符串。末尾加上 timestamp 和 recvWindow，单位是毫秒。
  3. 然后用 Secret Key 对这个字符串做 HMAC-SHA256。得到的摘要作为 signature 参数，附在请求后面。
  4. 请求头带着 API Key，参数里带着签名，Secret 不在网络上出现。币安还支持 RSA 和 Ed25519 密钥。它们是非对称签名，服务端不保存私钥。
  5. 网关按 API Key 查到 Secret，重算签名，再和请求里的比较。比较要用常量时间算法，否则攻击者能从响应耗时里逐位猜签名。
  6. 如果有人在路上把数量从 0.01 改成 10 呢？参数串变了，重算的签名对不上。没有 Secret，攻击者也算不出新签名。网关直接拒绝。
04 · 防重放 币安公开资料

原样重发的请求，签名照样正确

接受条件：服务器时间 − timestamp ≤ recvWindow　且　timestamp < 服务器时间 + 1s
  1. 签名能防篡改，但防不了一件事。攻击者截获完整请求，原样再发一遍，签名完全正确。这就是重放攻击。
  2. 币安规定，服务器时间减 timestamp，不能超过 recvWindow。timestamp 也不能比服务器快 1 秒以上。recvWindow 默认 5000 毫秒，最大 60000。
  3. 来算一个示例。把 timestamp 记为 T。服务器在 T 减 1 秒到 T 加 5 秒之间收到，都接受。正常请求 T 加 0.2 秒到达，通过。
  4. 攻击者截获了请求，在 T 加 8 秒重放。服务器一算，差了 8000 毫秒，超过 5000，直接拒绝。
  5. 但如果攻击者在 T 加 3 秒就重放呢？时间窗没过，签名也对。所以 recvWindow 只能缩短重放窗口。下单接口通常再用 newClientOrderId 去重，同一个只接受一次。
  6. 再看两个边界。recvWindow 设成 60000，重放窗口就拉长到 1 分钟。所以网络稳定时用小值。另外，客户端时钟偏慢，正常请求也会被拒，要先调服务器时间接口校准。

05 · KYC 币安公开资料 · 按地区变化

认证越充分，功能越多，额度越高

级别需要提交典型权益
未认证邮箱或手机号功能受限；自 2021 年起须认证才能交易和充提
已认证个人信息 + 身份证件 + 人脸识别加密货币充值、交易、提币
高级认证再加地址证明更高的法币额度
企业认证公司注册文件、股东与董事信息机构账户功能
KYC = Know Your Customer，了解你的客户　·　反洗钱 AML 合规的基础　·　另有制裁名单筛查
  1. 现在换到监管视角。监管要知道用户是谁，要阻止洗钱。这就是 KYC，了解你的客户。它是反洗钱合规的基础。
  2. KYC 的思路是分级。认证越充分，可用功能越多，额度越高。根据币安公开资料，未认证用户功能受限。自 2021 年起，新用户要完成认证，才能交易和充提。
  3. 已认证需要个人信息、身份证件和人脸识别，可以充值、交易和提币。高级认证再加一份地址证明，法币额度更高。
  4. 企业认证面向机构，要提交公司注册文件，以及股东和董事信息。注意，具体要求按国家和地区变化，以官网为准。
05 · KYC 状态机 业界通用做法的抽象

KYC 是一个会回退的状态机

  1. KYC 的处理流程是一个状态机。这张图是业界通用做法的抽象，不是币安内部的原样复刻。先看最顺的路径。注册完成是未开始，用户提交资料，进入自动审核。
  2. 自动审核会做证件识别、活体检测和名单筛查。证件和人脸比对通过，名单也没有命中，就直接批准。
  3. 如果置信度低，或者名单疑似命中，就转人工审核。人工可以批准，可以要求补充资料，也可以拒绝。用户补充资料以后，重新回到已提交。
  4. 命中制裁名单通常直接拒绝，还可能触发账户冻结。被拒绝的用户，可以在有限次数内重新提交。
  5. 最后注意，批准不是终点。证件过期或定期复审到期，状态会变成过期。用户要更新资料，重新提交。

  1. 把这些锁串起来，看一次完整攻击。第一步通常是钓鱼邮件。反钓鱼码就是用来识破它的。用户自己设一段暗号，币安官方邮件都会带上。
  2. 钓鱼者不知道暗号，邮件里就没有。假设用户没注意，在钓鱼网站输入了密码。攻击者拿到了第一把钥匙。
  3. 下一道锁是 2FA。没有开 2FA，攻击者直接登录成功。开了 2FA，攻击者还得拿到动态码。新设备登录还会触发二次验证，并通知用户。
  4. 假设这些也被突破了。下一道锁是提币白名单，只能向预先登记的地址提币。新增地址需要 2FA 和邮件确认。业界常见还有冷静期，示例是 24 小时内新地址不能提币。
  5. 冷静期的价值是争取时间。用户收到告警，可以自助冻结账户。风控看到新设备、新地址加大额，也会转人工审核。
  6. 这套防线也有局限。如果用户的邮箱也被攻破，邮件确认这一层就失效了。每一层都可能被绕过，所以要靠多层叠加，抬高攻击成本。
误区与边界

三个常见误区

✗ 开了 2FA 就不怕钓鱼

钓鱼网站可实时转发验证码　→ 通行密钥 / 硬件密钥绑定域名，防得住

✗ KYC 证明了谁在操作账户

只证明提交资料的人是谁；账户被出售、出借时发现不了

✗ 不泄露 Secret 就万事大吉

最常见的泄露：Secret 写进公开代码库 → 最小权限 + IP 白名单 + 关提币
  1. 最后看几个常见误区。第一个，开了 2FA 就不怕钓鱼。其实不然。用户在钓鱼网站上输入验证码，攻击者可以实时转发给真网站。
  2. 能防住这一类攻击的，是通行密钥和硬件安全密钥。它们和域名绑定，假域名拿不到有效签名。根据币安公开资料，这两种方式币安都支持。
  3. 第二个误区，以为 KYC 能证明谁在操作账户。KYC 只证明提交资料的人是谁。账户被出售或出借，KYC 发现不了。
  4. 第三个误区，觉得 Secret 保管好就够了。现实中常见的泄露，恰恰是把 Secret 写进了公开代码库。防护要靠最小权限、IP 白名单，以及关闭提币权限。
本集小结

记住三件事

  • 认证 ≠ 授权：登录成功只说明“你是你”，还要查“你能做什么”。
  • API 签名：HMAC 防篡改，timestamp + recvWindow 缩短重放窗口，订单号去重补漏。
  • 账户安全靠多层叠加：2FA、设备、白名单、冷静期、风控，每层都在争取时间。
