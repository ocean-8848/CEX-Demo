01 · 地址模型

链上只认地址：怎样把一笔转账归属到用户

对比项每用户独立地址共用地址 + memo / tag
原理每个用户派生专属地址同一地址，附加字段区分用户
典型链BTC、ETH、BSC 等 EVM 链XRP、XLM、EOS、TON、ATOM
识别用户按收款地址查按 memo / tag 查
用户出错点选错网络漏填或填错 memo
归集成本高：资金分散低：天然集中
为什么建地址免费、无最低余额建账户要冻结储备金
  1. 链上转账只认地址。交易所要把一笔转账归属到某个用户，有两种模式。第一种，给每个用户一个独立地址。第二种，所有人共用一个地址，再用附加字段区分。
  2. 独立地址常见于 BTC、ETH 和 BSC 这类链，按收款地址找用户。共用地址常见于 XRP、XLM 和 EOS，按 memo 或 tag 找用户。
  3. 两种模式的出错点不同。独立地址模式，用户容易选错网络。共用地址模式，用户容易漏填 memo。成本也不同。独立地址的资金很分散，后面要归集。共用地址的资金天然在一处。
  4. 为什么不统一？因为在 BTC 和 EVM 链上，创建地址免费。而 XRP 这类链，每个账户都要冻结一笔储备金。每人一个地址，成本太高。
01 · 地址派生 业界通用做法

线上只放主公钥：能生成地址，不能花钱

xpub 主公钥
在线 · BIP-32 / BIP-44
主私钥
离线保管，不在服务器上
序号派生地址 · 示例用户 ID
10010x9a3f…c41eU-58210
10020x27bd…08aaU-58211
10030xe1c0…9f35U-58212
EVM 链：同一个私钥在 Ethereum、BSC、Base 上对应同一个地址 → 埋下“充错链”的伏笔
  1. 独立地址是怎么来的？业界通常这样做。系统保管一个主公钥，叫 xpub。主私钥不放在线上。
  2. 有用户要充值，系统就按 BIP-32 和 BIP-44 规则派生地址。输入是主公钥加一个序号，输出是一个子地址。然后把地址和用户 ID，写进地址表。
  3. 下一个用户，序号加 1，再派生一个。地址表就这样一行一行长出来。监听服务以后就拿这张表，判断一笔转账属于谁。
  4. 关键在这里。线上服务手里只有公钥，所以它能生成地址，但不能花钱。就算服务器被攻破，攻击者也拿不到私钥。
  5. 再提一个细节。在 EVM 链上，同一个私钥在多条链上是同一个地址。比如 Ethereum、BSC 和 Base。这一点，后面讲充错链时会用到。
02 · 链上监听

监听服务把链上交易，变成内部事件

链上节点
监听服务Indexer
钱包服务
账本服务加余额
PENDING已发现
CONFIRMING确认数 +1
CREDITED已入账
UNLOCKED可提币
扫描每个新区块 → 每笔交易的收款地址去查地址表 → 命中就是一笔充值
方向：链上节点 → 监听服务 → 内部事件 → 钱包服务 → 账本
确认数 = 最新高度 − 交易所在高度 + 1
  1. 充值由区块链监听服务驱动，常叫 Indexer。它连着链上节点，不停扫描新区块。每个区块里的每笔交易，它都拿收款地址去查地址表。命中了，就是一笔转入交易所的充值。
  2. 发现一笔，就记一条充值记录，状态是已发现。交易进入区块后，每出一个新区块，确认数加 1，状态是确认中。
  3. 确认数达到入账阈值，监听服务通知钱包服务。钱包服务调用账本，给用户加余额，状态变成已入账。注意数据的方向。从链上节点来，经监听服务转成内部事件，最后才到账本。
  4. 很多交易所还设第二个阈值，叫解锁阈值，达到后才允许提币。确认数的算法很简单，最新高度减去交易所在高度，再加 1。刚上链时，确认数就是 1。

  1. 用动画看一遍。这里的阈值是示例，入账 3 个确认，解锁 6 个确认。用户刚广播交易，它还在内存池里，监听服务看到了，状态是已发现。
  2. 交易被打包进区块 101。最新高度是 101，确认数等于 101 减 101 加 1，也就是 1。状态变成确认中。
  3. 又出了 102 和 103 两个块。确认数是 103 减 101 加 1，等于 3，达到入账阈值。账本给用户加上 0.5 个 BTC，可以交易了。
  4. 继续出块到 106，确认数到 6，达到解锁阈值，这笔钱现在可以提走了。为什么要分两个阈值？因为能交易的钱，还困在交易所里。能提走的钱，一旦出错就追不回来。
  5. 根据币安公开资料，币安对 BTC 曾公开过一条规则。1 个确认入账，2 个确认可提币。具体参数会调整，以充值页面显示为准。
04 · 链重组 Reorg

节点发现更长的链，就丢掉自己的最后几个块

常见：1 块重组

两个矿工几乎同时出块，网络暂时分叉，很快收敛到一条

危险：深度重组

攻击者掌握大量算力，私下挖更长的链再公布，即 51% 攻击
比喻：两份草稿同时写到第 101 页，大家最终只认更厚的那本。不成立处：草稿是诚实分歧，而深度重组往往是故意的。
  1. 确认数防的是什么？防的是链重组。链重组是指，节点发现了另一条更长，或者说更重的链。于是它丢掉自己原来的最后几个区块，切换到新链。被丢掉的区块里的交易，在新链上可能根本不存在。
  2. 重组为什么会发生？最常见的是，两个矿工几乎同时出块，网络暂时分叉。很快大家收敛到一条链，这是 1 块重组，很常见。
  3. 危险的是另一种。攻击者掌握大量算力，私下挖一条更长的链，然后突然公布。这就是 51% 攻击，可以造成深度重组。算力越低的小链，发动这种攻击的成本越低。
  4. 打个比方，两份草稿同时写到第 101 页，大家最终只认更厚的那本。但比喻有一处不成立。草稿分歧是无心的，而深度重组往往是攻击者故意制造的。

入账之后，这笔充值不见了

+0.5

  1. 现在用动画看重组怎样让一笔充值消失。假设入账阈值是 2，这是示例。用户的 0.5 个 BTC 在区块 101 里。102 出块后确认数到 2，账本已经入账。
  2. 与此同时，攻击者从区块 100 之后，私下挖另一条链。他的 101 撇里，没有这笔充值。
  3. 攻击者的链挖到 103 撇，比原链更长，然后公布出来。全网节点按规则，切换到更长的这条链。
  4. 原来的 101 和 102 被丢弃，充值在链上消失了。可账本已经加了余额。如果攻击者早就把余额卖掉提走，损失由交易所承担。这就是重组双花，状态记为入账后重组损失，要人工处理。
  5. 反过来看。如果阈值设成 6，重组发生时这笔充值还没入账。它只是被标记为丢弃，用户余额没变，交易所也没有损失。确认数阈值越高，攻击者要重写的块越多，成本越高。
03 · 阈值权衡 示例，非币安当前参数

安全与等待时间的权衡

链出块时间 约示例入账阈值示例等待
BTC10 分钟1–210–20 分钟
ETH12 秒6–64 或 finalized1–13 分钟
BSC3 秒以内15 左右1 分钟以内
以太坊 Finality：区块 finalize 后，推翻它要销毁至少 1/3 质押 ETH
防护：小链高阈值 · 监控算力与重组深度，异常暂停充值 · 入账与解锁分开
  1. 阈值怎么定？来算两个示例。BTC 大约 10 分钟出一个块，阈值 2，就要等 20 分钟左右。ETH 大约 12 秒一个块。阈值 64，就是 64 乘以 12 秒，约 13 分钟。
  2. BSC 出块在 3 秒以内，阈值 15 左右，1 分钟内就能到账。注意，这张表都是示例，不是币安当前参数，以充值页显示为准。
  3. 以太坊合并之后，有了最终确定性。区块被确定以后，推翻它要销毁至少三分之一的质押 ETH。所以在以太坊上，更合理的做法是等待确定状态，而不是只数区块。
  4. 防护上有三招。小市值、算力低的链，设更高的确认数。监控链的算力和重组深度，异常时暂停充值。还有就是入账和解锁分开设阈值。
05 · 常见失败 业界通用情况

同一个地址，选错了网络

Ethereum
0x9a3f…c41e
BSC
0x9a3f…c41e
Base
0x9a3f…c41e
资产确实到了交易所控制的地址，但 Base 上没人在监听 → 不会自动入账
找回：交易所人工在 Base 上用同一私钥签名转出
冷钱包或 MPC 场景，操作成本很高
若该地址是合约钱包，Base 上可能没有部署这个合约 → 资产可能永久丢失
充值前：确认充值页网络 = 发送方网络
  1. 来看第一类常见失败，充错链。假设交易所只在 BSC 上，监听你的这个地址。前面说过，EVM 链之间地址相同。用户在发送方钱包里，却选了 Base 网络。
  2. 结果是，资产确实到了交易所控制的地址。但交易所在 Base 上没有监听它，系统不会自动入账。
  3. 能找回吗？可以试。交易所要人工在 Base 上，用同一个私钥签名把钱转出来。如果这把私钥在冷钱包或 MPC 里，操作成本很高。
  4. 更糟的情况是，目标地址是一个合约钱包。合约在 BSC 上部署了，在 Base 上却可能根本不存在。这时资产可能永久丢失。所以充值前，一定确认充值页的网络和发送方的网络一致。
05 · 常见失败 币安公开资料

共用地址：memo 才是你的门牌号

交易 · 示例收款地址memo归属
tx 8f1a…rEx…共用104857—
tx 3c77…rEx…共用220391—
tx b904…rEx…共用空—
无主充值队列
用户提交 txHash
人工核实找回不保证成功 · 可能收费
  1. 第二类常见失败，漏填 memo。在 XRP 这类共用地址的链上，所有用户的充值都打到同一个地址。系统只能靠 memo 来分辨是谁的。
  2. 第一笔交易带着 memo 104857，系统查表，找到对应用户，给他入账。
  3. 第二笔 memo 是 220391，同样找到用户。但第三笔没有 memo。钱到了交易所的地址，系统却不知道该记给谁。
  4. 这笔钱会进入无主充值队列。用户要提交交易哈希，申请人工找回。根据币安公开资料，需要 memo 的币种，充值页会强制提示。漏填后可以申请找回，但不保证成功，还可能收费。
本集小结

记住三件事

  • 归属靠地址或 memo：线上只放公钥，能收钱不能花钱。
  • 确认数 = 推翻成本：入账阈值管能交易，解锁阈值管能提走。
  • 重组发生在入账前只是丢弃，发生在入账后就是交易所的损失。

提币、冷热钱包与储备金证明
钱怎样安全地流出去？交易所怎样证明自己真的有钱？
  1. 最后小结三点。第一，充值归属靠地址或 memo。线上只放公钥，能收钱，不能花钱。
  2. 第二，确认数代表推翻成本。入账阈值决定什么时候能交易，解锁阈值决定什么时候能提走。
  3. 第三，重组如果发生在入账前，只是丢弃一条记录。发生在入账后，就是交易所的真实损失。所以阈值要按链的安全性来定，小链要更保守。
