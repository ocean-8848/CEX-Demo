一句话理解 · 打个比方

任何时刻，每一种币，在对应的链上都付得出

首要目标：用户要提走的每一种币，在对应的链上，都有足够余额可付。
门店收银台：只放当天找零
→ 热钱包
总部金库：两个经理签字才能调
→ 冷钱包
A 店人民币不能给 B 店找美元
→ 不同链、不同币 = 不同库存
比喻不准的地方：超市运钞只是慢；交易所跨链调拨可能要过跨链桥，桥本身可能被攻击。
  1. 金库运营的首要目标只有一个。任何时刻，用户要提走的每一种币，在对应的链上都有足够余额可付。
  2. 打个比方，交易所金库像连锁超市的调度中心。门店收银台只放当天找零的现金，这是热钱包。总部金库放大部分现金，调拨要两个经理签字，这是冷钱包。
  3. 门店之间的现金不能直接混用。A 店的人民币，不能给 B 店的顾客找美元。对应到交易所，不同链、不同币种是不同的库存。
  4. 比喻不准的地方在于运钞方式。超市运钞只是慢一点。交易所跨链调拨可能要经过跨链桥，桥本身可能被攻击。

  1. 先换成资产负债表的视角。左边是资产，交易所持有什么。右边是负债和权益，交易所欠谁。
  2. 资产侧有链上钱包余额，按热、温、冷，按币种按链分开。还有在途资金和法币备付金。
  3. 负债侧最大的一项是用户负债，也就是全部用户的可用余额加冻结余额。还有已扣款、未上链的待处理提币。
  4. 平台自有的东西单独成栏。做市和闪兑库存，手续费累计，以及保险基金和 SAFU。专项基金要专款专用。
1:1 储备 · 示例数字

按美元总值相等，不等于付得出

  1. 1比1储备的定义是逐币种的。对每一种币，交易所持有的用户资产，都要大于等于用户负债。
  2. 举个示例。用户在平台上有100万美元的 BTC，还有100万美元的 USDT。平台各自持有对应数量，两种币的储备率都是100%。
  3. 现在换一种做法。平台拿100万美元的自有代币，冒充 BTC 储备。按美元总值算，资产200万，负债200万，看起来还是100%。
  4. 但用户来提 BTC 时，平台付不出 BTC，BTC 的储备率其实是0。FTX 的问题之一，就是资产端大量持有低流动性的关联代币。
  5. 所以金库的第一个指标是逐币种储备率，等于平台持有除以用户负债。低于100%，立即告警，等级是 P0。

  1. 金库要防八类风险。先看前两类。单链流动性不足，是某条链的提币集中爆发。币种错配，是负债是 BTC，资产却是 USDT。
  2. 资金混用，是自有资金和用户资金放在同一个账户，有挪用风险。稳定币也会出事，可能脱锚，也可能被发行方冻结。
  3. 法币通道可能中断，比如合作银行终止服务。挤兑，是负面消息引发集中提币，最终可能流动性枯竭。
  4. 最后是坏账和内部挪用。坏账来自穿仓、闪兑报价错误或被盗。内部挪用，是高管绕过审批调用用户资金。
防线分层

前四层预防，后两层兜底

第 1 层 账户隔离用户资金、自有资金、专项基金分账漏：账面隔离但钱包未隔离
第 2 层 1:1 储备逐币种；每日对账；PoR 定期公开漏：快照之间的挪用
第 3 层 水位调拨热温冷水位、跨链再平衡漏：全链同时挤兑
第 4 层 敞口对冲手续费收入、做市库存、闪兑库存
第 5 层 专项基金合约保险基金、SAFU兜底
第 6 层 坏账处置ADL、平台资本、社会化分摊兜底
  1. 对应的防线有六层。第1层是账户隔离，用户资金、平台自有资金和专项基金分账。它的漏洞是，账面隔离了，钱包却没隔离。
  2. 第2层是逐币种1比1储备，每日对账，定期公开储备金证明。漏洞是，两次快照之间的挪用看不见。
  3. 第3层是水位与调拨，管好热温冷水位和跨链再平衡。第4层是敞口对冲，处理手续费收入和库存的价格风险。
  4. 前四层是预防。第5层是专项基金，包括合约保险基金和 SAFU。第6层是坏账处置，ADL、平台资本和社会化分摊。这两层是兜底。
  5. 注意一个局限。全部用户同时提走全部资产时，没有任何一层能做到毫无延迟。冷钱包出账需要时间，这是安全设计的代价。

  1. 同一个币在不同链上，是不同的库存。比如 USDT 有 Tron、Ethereum 等多个版本。每个版本都要单独管水位。
  2. 看这张示例表。USDT-Tron 的用户负债是80亿。热钱包3.2亿，温钱包8亿，冷钱包69亿。资产略大于负债，差额是平台自有部分。
  3. 热钱包覆盖率，等于热钱包余额除以用户负债。3.2亿除以80亿，是4%。BTC 是3000除以10万，3%。
  4. 覆盖率要设上下限，示例是1%到5%。太低，提币会排队。太高，被盗时损失大。
  5. 再算耗尽时间。假设 USDT-Ethereum 6小时净流出1.5亿，每小时就是2500万。热钱包1亿，只够撑4小时。
  6. 示例规则是，耗尽时间少于4小时就告警，这里已经到了线上。该从温钱包补充，或者从 Tron 链再平衡。温钱包5亿，按这个速度还能撑20小时。
  7. 其他指标还有几项。单一稳定币超过稳定币储备的60%要告警。单一银行超过法币余额的40%要告警。Gas 币不够3天消耗，也要告警。
冷 → 热 调拨 · 示例

补一次热钱包，也要过白名单、审批和签名

单笔金额 · 美元等值审批
≤ 100 万1 人
100 万 – 1,000 万2 人
> 1,000 万2 人 + 风险负责人
  1. 热钱包水位低了，就要从冷钱包补。这笔调拨本身也要走审批流。来看一个示例，从冷钱包调3000万美元等值的 USDT 到热钱包。
  2. 第一步是规则校验。调拨只能发往内部白名单地址。白名单本身的变更，需要3人审批。
  3. 第二步是分级审批。示例规则是，100万美元以内1人审批，100万到1000万要2人。超过1000万，要2人再加风险负责人。这笔3000万，走最高一级。
  4. 第三步是签名。发起人、审批人、签名人，三个角色分离，任何一人都不能单独把钱调走。签名人还要在签名设备上复核目标地址和金额。
  5. 广播之后等确认数，到账才算完成。如果超过预期确认时间的3倍还没到账，就进入对账异常，人工核实。
  6. 还有两条规则。冷钱包单笔出账，不超过冷钱包余额的10%。常规出账只在工作时段，紧急出账要额外审批。所以挤兑时，补充速度受审批人在线时间限制，要预先排班。
跨链再平衡 · 稳定币与法币通道

A 链堆积，B 链见底：怎么把钱挪过去

  1. 用户在 A 链充值、在 B 链提币，A 链的库存就变多，B 链变少。金库要把资金从 A 链挪到 B 链。
  2. 第一种方法是发行方换链。在 A 链把稳定币交还发行方，在 B 链重新发行。没有桥风险，但依赖发行方的处理时间和最小额。
  3. 第二种是跨链桥，快，但桥可能被攻击。第三种是场内对冲，在 A 链卖、B 链买，或和做市商场外互换。代价是价差和对手方风险。
  4. 第四种是引导用户，比如调整 B 链的提币手续费，甚至暂停 B 链提币。零成本，但影响体验。
  5. 稳定币本身也是金库风险。发行方可以在链上冻结地址。所以要同时持有多种主流稳定币，并给单一发行方设上限。法币通道也一样，要多银行、多通道。
  6. 据公开报道，2022年9月，币安把用户持有的三种稳定币自动转为 BUSD。它们是 USDC、USDP 和 TUSD。2023年2月，纽约州金融服务部要求 Paxos 停止新铸 BUSD。之后币安逐步停止了 BUSD 相关产品。
敞口对冲 · 示例数字

平台自己的钱，也会被币价拖累

  1. 平台自有资金也有币价敞口。最常见的是手续费收入，因为手续费以 BTC、ETH 和各种代币收取。
  2. 举个示例。平台本月手续费收入500个 BTC，BTC 价格6万美元，价值3000万美元。
  3. 如果不对冲，BTC 下跌20%，收入就缩水600万美元。500乘以6万，再乘以20%。
  4. 如果每天把当天的手续费换成 USDT，敞口就只剩一天的价格波动。
  5. 其他敞口还有三类。做市库存，用永续合约做空对冲。闪兑库存，在现货市场或向做市商平盘。理财期限错配，要保留赎回缓冲。
挤兑压力测试 · USDT-Ethereum · 示例

哪条链、哪个币、第几小时会耗尽

  1. 金库最重要的演练，是挤兑压力测试。输入是真实负债和真实余额。输出是哪条链、哪个币、第几小时会耗尽。
  2. 情景分三档，都是示例。温和是24小时提走5%，看热钱包能否覆盖。严重是15%，看温钱包补充速度。极端是30%，而且集中在2条链。
  3. 拿 USDT-Ethereum 来算严重情景。负债50亿，15%就是7.5亿，每小时约3100万。热钱包1亿，大约3小时就耗尽。
  4. 接着动用温钱包。温钱包5亿，又能撑16小时。热加温一共6亿，还差1.5亿，必须在第19小时前从冷钱包补上。
  5. 极端情景更难。提走30%就是15亿，每小时约6200万。温钱包撑到第10小时左右就见底。缺口9亿，全靠冷钱包紧急出账。
  6. 所以关键参数是冷钱包补充速度。它取决于审批人到位时间、签名设备的物理位置和链的确认时间。演练要真的测出补充耗时，再更新水位下限和排班。
  7. 记住一句话。1比1储备的交易所，挤兑时有钱但可能慢。非1比1储备的交易所，慢了之后就没钱。真实挤兑往往比平均情景更集中，更极端。
兜底顺序

损失发生后，按类型走不同的兜底池

  1. 如果损失已经发生，谁来承担？不同类型的损失，走不同的兜底池。
  2. 合约穿仓，先用合约保险基金。保险基金不足，就触发自动减仓 ADL。
  3. 被盗或系统事故，用 SAFU 基金。杠杆借贷坏账，用杠杆风险准备。这两池都不足时，由平台资本承担。
  4. 平台资本是最后一道自愿的防线。再不足，就是社会化分摊或破产程序。这意味着用户承担损失，是最差的结果。
  5. 专项基金必须和运营资金隔离。专项基金被挪作他用，兜底就是空的。

局限与权衡 · 小结

安全和流动性，永远在拉扯

权衡一侧另一侧常见做法
安全 vs 流动性热钱包少：被盗损失小挤兑时提币慢动态水位
收益 vs 储备用户资金出借：有收益破坏 1:1 储备用户资金不出借
审批 vs 速度多人审批：防挪用紧急时慢预设紧急流程
跨链效率 vs 桥风险用桥：快桥被攻击损失大优先发行方换链
1:1 储备是必要条件，不是充分条件：签名设备失联、审批人缺席、链拥堵，用户依然提不出币。

记住三件事

  • 储备要逐币种、逐链看，按美元总值算不够。
  • 金库管两件事：有没有钱，和能不能及时付出去。
  • 损失按类型走不同兜底池；专项基金必须隔离。

  2. 用户资金出借能赚收益，但会破坏1比1储备。多人审批能防内部挪用，但紧急时慢，所以要预设紧急流程和事后复核。
  3. 还要记住，1比1储备是必要条件，不是充分条件。储备还在，签名设备失联、审批人缺席、链拥堵，用户依然提不出币。
  4. 小结三点。第一，储备要逐币种、逐链地看，按美元总值算不够。
  5. 第二，金库运营管两件事。有没有钱，靠储备和对账。能不能及时付出去，靠水位、调拨审批和压力测试。
  6. 第三，损失按类型走不同的兜底池，专项基金必须隔离。
