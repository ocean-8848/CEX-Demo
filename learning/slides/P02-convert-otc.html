  1. 本集分三段。闪兑，大宗 OTC，快捷买币。它们有一个共同点：用户的对手方是平台，或者平台指定的报价方。不是订单簿上的其他用户。
  2. 打个比方，闪兑像机场的货币兑换柜台。柜台报一个牌价，承诺10秒内按这个价卖给你。大客户来换100万，经理单独打电话问价，这就是 OTC。
  3. 比喻在一点上不成立。柜台牌价变得慢，加密价格每秒都在变。这10秒里，平台等于免费送出一个选择权。这是本集的核心问题。

闪兑的两种模式与报价有效期

市价：用 X 换 Y → 预览 → 报价 + 倒计时 → 确认
币安声明闪兑不收手续费
限价：设目标价和有效期
行情短暂触及限价，不一定成交
FAQ：报价考虑交易规模且是实时价
→ 与现货最新成交价不同 · 零手续费 ≠ 零成本
询价接口 validTime = 10s | 30s | 1m 默认 = 10s 过期 → 重新询价 限价单 expiredType = 1 | 3 | 7 | 30 天
  1. 先看闪兑。根据币安公开资料，它有两种模式。市价模式，输入用什么换什么，点预览，页面给出报价和倒计时，点确认就成交。币安声明闪兑不收手续费。
  2. 报价有有效期。闪兑接口的询价请求，有效期可以选10秒、30秒或1分钟，默认10秒。过期就要重新询价。
  3. 限价模式，设一个目标价和有效期，接口里可选1天、3天、7天或30天。行情短暂碰到限价，订单也不一定成交。
  4. 币安 FAQ 还说明，闪兑价格和现货最新成交价不同。因为报价考虑了交易规模，而且是实时价格。所以零手续费，不等于零成本。
Money Flow · 示例

先给用户币，再去市场补库存

  1. 来看钱怎么走，数字是示例。用户接受报价，系统先冻结他的10000 USDT。
  2. 接着是一组原子分录。扣掉用户的 USDT，转进平台闪兑账户。同时从平台的 ETH 库存里，划3.992个 ETH 给用户。用户立刻拿到币，不用等对冲。
  3. 然后是平台自己的交易。它用收到的 USDT，去订单簿或外部做市商买回 ETH，回补库存。这一步可以晚几百毫秒，也可以和别的单合并。
  4. 出错点在库存。划币要求平台有足够的 ETH。库存不够，平台只能拒绝报价，或者先买后卖。
RFQ State Machine · 业界通用做法

一张报价的一生

  1. 把它画成状态机。用户请求报价，进入已报价。报价里带着过期时间戳和签名，倒计时开始。
  2. 倒计时结束还没确认，进入已过期。已过期不扣任何资金，用户重新询价，拿一个新报价。
  3. 在有效期内确认，进入已接受。服务端校验签名和有效期，再检查余额和风控。不通过，就是已拒绝。
  4. 通过以后，账本原子划转成功，进入已成交。用户能看到的状态，到这里为止。
  5. 后面两个是平台内部状态。敞口进入对冲队列，叫待对冲。对冲单成交，叫已对冲。
  6. 注意一个细节。过期由服务端统一判断，用户端的倒计时只是显示。否则两边时钟不同步，判断就会出错。
Call Chain · 示意服务名

询价、接受、对冲

  1. 再看服务之间怎么调用。服务名是业界通用的拆法，币安内部命名没有公开。用户请求报价，闪兑服务转给报价引擎。
  2. 报价引擎读取订单簿深度和中间价，算出报价。比如2505，有效期10秒，带签名。注意，报价引擎只读行情，不写账本。
  3. 用户接受后，闪兑服务校验签名和有效期，再问过风控。然后调用账本，原子地扣 USDT、加 ETH。
  4. 最后发布敞口事件：平台空了3.992个 ETH。对冲服务先做内部净额，再把差额送进撮合引擎。
  5. 内部净额是什么意思？A 用户买 ETH，B 用户卖 ETH，两笔敞口互相抵消，只对冲差额。对冲时价格已经变了，这部分损失由平台承担。
Quote Engine · 业界通用做法

报价 = 中间价 × (1 + 方向 × 总价差)

  1. 报价是怎么算出来的？业界通常这样做。报价等于中间价，乘以1加上方向乘总价差。中间价是买一和卖一的平均值，也可以取多个报价源的加权。
  2. 总价差由四部分组成。第一，基础价差，这是平台的目标利润。第二，规模加价。金额越大，对冲时吃的深度越多，滑点越大，要提前加进价格。
  3. 第三，波动加价。有效期越长、行情越剧烈，平台被动承担的风险越大。
  4. 第四，库存偏移。平台手上 ETH 太多，就让用户买 ETH 的报价便宜一点，请用户帮忙消化库存。
  5. 示例里，总价差是0.2%。2500乘以1.002，报价2505。用户得到10000除以2505，约3.99202个 ETH。
P&L per Trade · 示例

价差收入，减去三种损失

单笔盈亏 = 价差收入 − 逆向选择损失 − 对冲延迟损失 − 对冲滑点
  1. 平台每一笔的盈亏，可以拆成四项。价差收入，减去逆向选择损失，减去对冲延迟损失，再减去对冲滑点。
  2. 用示例算一遍。价差收入是10000乘0.2%，约20 USDT。
  3. 报价期间 ETH 上涨了0.05%，对平台不利，损失5 USDT。
  4. 对冲滑点2个基点，再损失2 USDT。平台净赚约13 USDT。
  5. 注意，价差收入是确定的，后面几项是随机的。平台关心的是1000笔的平均值和尾部风险，不是单笔结果。
Adverse Selection · 示意

谁会点确认？

  1. 现在是本集最关键的风险：逆向选择。意思是，愿意接受报价的用户，恰好是让平台亏钱的那部分用户。
  2. 正常用户在倒计时内随便哪一刻点确认。市场价只小幅波动，平台赚到价差，平均是正的。
  3. 另一类用户同时盯着其他交易所。他等到有效期快结束，外部价格已经朝有利方向走，幅度超过价差，就点确认。平台这一笔亏钱。
  4. 价格朝不利方向走，他就让报价过期，什么也不付。这类订单流，叫毒性流量。
  5. 平台等于卖出了一份免费期权。用户有权选择成交或不成交，平台却没收权利金。
Defenses · 业界通用做法

每条防线都有代价

防线作用代价
缩短报价有效期减少等待有利变动的时间来不及确认
按波动率加宽价差小幅变动覆盖不了价差正常用户也付更多
按用户分层报价异常账户加宽价差或限额可能误伤
接受时重新比价超出容忍区间就拒绝看到报价已失效
限制频繁询价只询价不成交的账户限流要识别正常比价
  1. 平台怎么防？业界通用做法有五条，每条都有代价。第一，缩短报价有效期。代价是用户来不及确认。
  2. 第二，按波动率加宽价差，代价是正常用户也付更高价格。第三，按用户分层报价。接受率和盈利异常的账户，加宽价差或限额，代价是可能误伤。
  3. 第四，接受时重新比价。市场价超出容忍区间，就拒绝成交，要求刷新。第五，限制只询价不成交的账户。
  4. 还有库存风险。业界通常先做内部净额，超过阈值再拆单进订单簿。深度不够，就找外部做市商。敞口超过上限，就加宽这个方向的价差，或者暂停报价。
  5. 失败场景也要预案。行情源延迟时，报价引擎读到旧价格，套利者会集中接受。所以行情时间戳超过阈值，就暂停报价。极端行情直接熔断，提示服务繁忙。
OTC Desk · 公开资料 + 示例

大宗 OTC：交易台单独报价

  1. 第二个产品，大宗 OTC。大额交易不进订单簿，由平台交易台单独报价。根据币安公开资料，手动现货询价最低20万美元，现货询价不收手续费。账户必须预先充足资金。
  2. 还有一种意向撮合，叫 IOI。平台把大额买方和卖方在场外配对，平台自己不持有敞口。
  3. 来算一笔示例。客户买50个 BTC，参考价60000。基础价差0.05%，冲击成本0.1%，持仓风险溢价0.05%，加起来0.2%。
  4. 报价是60000乘以1.002，等于60120。名义金额300万 USDT，平台预期毛利6000 USDT。实际利润，取决于对冲成本。
  5. 成交后，账本当天就完成双方划转，因为双方资产都在平台托管。对冲业界通常用 TWAP 拆单，持续几个小时，期间平台一直扛着敞口。
  6. 还有一个坑叫赢家诅咒。客户同时向几家平台询价，赢得报价的，往往是报价最差的那家。业界通常跟踪客户的询价成交比，调整报价。
Buy with Card · 公开资料 + 示例

快捷买币 = 法币收款 + 一次闪兑

  1. 第三个产品，银行卡买币。根据币安公开资料，支持借记卡和信用卡，卡片需要开通 3DS。3DS 就是发卡行在付款时，再验证一次持卡人。
  2. 资金流是这样的。持卡人授权1000美元，支付通道回调付款成功。法币网关做一次内部闪兑，BTC 马上记进用户账户。
  3. 但平台要过几天，才从收单机构真正收到法币。中间这几天，是平台在垫资。所以快捷买币，就是法币收款加一次闪兑。
  4. 算一笔示例。卡支付手续费2%，是20美元。剩下980美元买 BTC，价差0.3%，约2.9美元。
  5. 平台这边，支付通道收1.5%，15美元。拒付准备金按0.3%计提，3美元。平台毛利约4.9美元。利润率不高，它的主要价值是拉新。
Chargeback · 业界通用做法

风险在几周之后到来

  1. 快捷买币最大的风险是拒付。持卡人可以通过发卡行，撤销已经完成的卡交易。所以已到账不是终态，拒付窗口通常以月计。
  2. 看一条典型攻击链。黑产买到被盗卡信息，注册新账户，先小额试卡。
  3. 试卡成功，就大额买币，然后立刻提到外部地址。
  4. 几周后，真实持卡人发现盗刷，申请拒付。收单机构把钱扣回，币早就没了，损失落在平台。
  5. 关键节点是秒提。提币冷却期，直接切断买完就提走。小额试卡也是早期信号。业界通常再加上设备指纹和首单限额。
  6. 3DS 的意义是责任转移。按卡组织规则，通过 3DS 认证后，非本人交易类的拒付损失，一般转由发卡行承担。但它只覆盖欺诈类拒付。
本集小结

记住三件事

  • 对手方是平台：零手续费 ≠ 零成本，价差就是费用。
  • 单笔盈亏 = 价差 − 逆向选择 − 对冲延迟 − 滑点；有效期是免费期权。
  • 快捷买币的风险在几周之后：拒付、冷却期、3DS 责任转移。
