合约网格另选：方向 · 杠杆 · 示例参数
  1. 先看网格。用户填五个参数，下限、上限、网格数、类型和投入资金。根据币安公开资料，有现货网格和合约网格。合约网格还能选方向和杠杆。
  2. 网格数是 N，就画 N 加1条线。等差网格，相邻两线的价格差固定。示例区间80到120，N 等于10，间距是4 USDT。
  3. 等比网格，相邻两线的价格比固定。比值是1.5开10次方，约等于1.04138。所以线在低处密，在高处疏。
  4. 两种画法，决定了每一格能赚多少。下面我们来算。
Per-Grid Profit · f = 单边手续费率

每一格往返一次，赚多少

每格资金 B = 投入 ÷ N　·　数量 qᵢ = B ÷ Pᵢ
利润 = qᵢ × (Pᵢ₊₁ − Pᵢ) − f × qᵢ × (Pᵢ + Pᵢ₊₁)
  1. 每格资金 B，等于投入资金除以 N。每一格买入的数量，是 B 除以这一格的下沿价格。一次买卖往返，赚上下两线的差价，再减去两次手续费。
  2. 示例，投入1000 USDT，手续费率0.1%。等差网格最低一格，80到84。数量是100除以80，等于1.25。利润约4.795 USDT，也就是4.80%。
  3. 最高一格，116到120。数量约0.8621，利润约3.245 USDT，只有3.24%。等差网格低价区利润率高，高价区低。
  4. 等比网格每格利润率相同，约3.934%，适合宽区间。注意，网格太密时，每格利润率会小于0。示例，等差200格时，最高一格约负0.03%，每成交一次都亏钱。
Grid Running · 等差 80–120 · 示例

一格成交 → 相邻线反向补挂一单

  1. 现在让网格跑起来，示例起始价100。创建时，系统先市价买入底仓，因为上方每一格都需要一份币等着卖出。然后下方挂买单，上方挂卖单。
  2. 价格跌到96，96的买单成交。网格的核心动作只有一个，一格成交，就在相邻线反向补挂一单。于是在100挂出卖单。
  3. 价格继续跌到92，92的买单成交，在96补挂卖单。
  4. 价格反弹到96，刚才的卖单成交。92到96这一格完成一次往返。数量是100除以92，利润约4.14 USDT。
  5. 价格再回到100，96到100这一格也完成往返，利润约3.96。两格累计约8.11 USDT。价格来回穿越越多，往返越多。
State Machine · Call Chain · strategy-engine 为示例服务名

网格的状态机

  1. 网格的状态机很简单。初始化时买底仓、挂单，然后进入运行。运行中每一格成交，就补挂一张反向单。
  2. 价格高于上限，币全部卖光，只剩 USDT，不再享受上涨。价格低于下限，全部买满，只剩币，承担全部下跌。这两个状态就是网格失效。除非开启移动网格选项，网格不会自动移动区间。
  3. 再看调用链。策略引擎批量下限价单，每单走正常风控，挂进订单簿。触发靠的是预埋限价单，价格到了，撮合引擎直接成交，策略引擎不用盯价。
  4. 策略引擎只在成交之后动作。它从 Kafka 成交流消费事件，补挂反向单。clientOrderId 由策略 ID、格号和轮次组成。重复消费同一事件时，订单服务据此去重。
Grid PnL · Failure Case · 示例

总收益 = 网格利润 + 浮动盈亏

  1. 用户的总收益分两部分。网格利润来自波动，是已完成往返的累计。浮动盈亏来自趋势，是持仓市值减去成本。
  2. 看一个失败示例。起始价100，价格单边跌到60，网格全部买满。用户持有约10.35个币，市值约621 USDT，现金约35 USDT。
  3. 不计途中的网格利润，总亏损约344 USDT。单边下跌时，浮动亏损可以远大于网格利润。另一种失败是网格过密，成交很多，网格利润却是负的。
  4. 平台怎么赚钱？每次成交都收手续费，策略工具本身通常不另收费。平台的风险是，大量网格挂在同一价位，形成假深度。行情突破时被集中吃掉，深度瞬间变薄。
DCA · Convert Recurring

定投：固定金额，定期买入

  1. 第二个产品是定投，每隔固定时间，用固定金额买入同一资产。根据公开报道，币安的定投从2025年起，迁移到闪兑的定期买入。周期从每小时到每月可选。
  2. 示例，三期各投100 USDT，价格分别是10、5、10。分别买到10个、20个、10个，一共40个。
  3. 平均成本是300除以40，等于7.5，低于三次价格的算术平均8.33。价格越低，买得越多。但定投不消除下跌风险，它只平滑买入时点。
  4. 系统侧有两个要点。失败的一期不补执行，否则用户会在不知情时买入两倍金额。同一时刻触发的大量定投单，要在时间窗里打散执行，否则小币种盘口会被打穿。
TWAP · Algo Order

TWAP：把大单在时间上摊开

  1. 第三个产品，TWAP 算法单，也就是时间加权平均价格。它把一笔大单，在指定时间里均匀拆成很多小单。根据公开资料，币安向部分用户提供这类算法单。
  2. 示例，买100个 BTC，2小时完成。每30秒一片，一共240片，每片约0.4167个。母单冻结全部资金，子单成交后逐步消耗。
  3. 一次性市价买入，可能吃掉多档深度，示例滑点0.5%。拆单之后，每一片的冲击接近0。子单量还会加随机扰动，避免别人识别出固定节奏。
  4. 母单状态由子单汇总得出，价格超出限价就暂停。一个风险是行情服务延迟，策略引擎按旧价格下单。防线是，行情时间戳过期就暂停发单。

Copy Trading · Call Chain · 示例

跟随者一定晚于带单员

  1. 看调用链。带单员下单，撮合成交，成交事件写进 Kafka。跟单服务消费事件，为每个跟随者计算子订单。
  2. 子订单分批经过风控，检查保证金和杠杆上限，再进入撮合。所以跟随者的订单，一定晚于带单员。
  3. 示例，500个跟随者的子订单，集中进入同一方向，把价格推高。带单员成交在100.00，跟随者成交在100.03到100.12之间。
  4. 跟随者平均成交100.06。100万 USDT 跟单资金，单向成本就是600 USDT。所以平台会限制跟单资金。资金太大，子订单本身就会推动价格，策略不再可复制。
Profit Sharing · High-Water Mark · 官方 FAQ

每周结算：总盈亏 × 比例 − 已分成

本期分成 = max[ (已实现 + 未实现盈亏) × 分成比例 − 已分成金额 , 0 ]
  1. 分成怎么结算？根据官方 FAQ，每周一零点 UTC，系统对每个跟单组合的总盈亏拍快照。总盈亏是已实现加未实现。2024年9月23日起，基础从已实现盈亏改成了总盈亏。
  2. 公式是总盈亏乘以分成比例，减去已分成金额，最小为0。示例，比例10%，第一周总盈亏涨到200，分成20。跟随者净得180，未计手续费。
  3. 第二周总盈亏回落到150。150乘以10%是15，减去已分的20，小于0，本周不分成。这就是高水位线，亏损之后必须先赚回来。
  4. 再补一个示例，第三周涨到300。300乘以10%是30，减去已分的20，本周分成10。
  5. 跟单的风险也要看清。带单员可以用小资金高杠杆，赌出漂亮的收益率。排行榜只显示活下来的人，这是幸存者偏差。带单员一次爆仓，所有跟随者会同时被强平。
Strategy Engine Architecture · 业界通用做法

策略引擎：撮合引擎的客户端

  1. 最后看系统架构。策略引擎有三种输入，行情、成交流和定时调度。触发器据此判断，价格到了，成交回报到了，或者时间到了。
  2. 触发后读取策略状态，再过策略风控，比如单策略资金上限和止损。然后过限频。限频有两层，单策略限频防刷单，全局令牌桶防止挤占人工下单。
  3. 关键是，策略引擎在撮合引擎之外。它和普通 API 用户走同一条下单路径。把策略逻辑放进撮合引擎，会破坏确定性和吞吐。
  4. 还有三个业界做法。确定性生成 clientOrderId，防止重复下单。价格穿越大量触发点时，按优先级分批下单。引擎重启后，与订单服务对账，补发或撤销。
Summary

记住三件事

  • 策略交易 = 平台替你挂单撤单：策略引擎在撮合之外，走普通下单路径。
  • 网格利润来自波动，浮动盈亏来自趋势；单边行情网格失效。
  • 跟单有滑点；分成按总盈亏 + 高水位线每周结算。
