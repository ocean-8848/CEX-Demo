手续费或补贴记成支出

Referral · 官方与第三方口径

返佣比例：官方说什么，第三方说什么

官方 · 币安学院 Referral Pro Mode

  • 返现给被推荐人：最多 20%
  • 佣金比例低于 20%：可全部让出
  • 每个账户最多 50 个推荐码
  • 注册时绑定，不能更改或解除
  • 官方未给出基础佣金比例

第三方资料

  • 现货基础佣金：历史上 20%
  • 持有 ≥ 500 BNB：最高 40%
  • 2024-03 起部分地区：10%–15%
  • 合约：10%–20%
部分第三方写"可让出 0%–50%"，与官方"最多 20%"不一致 → 本集以官方为准
  1. 返佣比例的来源分两层。先看官方。根据币安学院的推荐专业模式文章，推荐人可以用进度条设置返现比例。他能把佣金的一部分让给被推荐人，最多20%。
  2. 如果推荐人的佣金比例低于20%，可以全部让出。每个账户最多50个推荐码。推荐关系在注册时绑定，之后不能更改或解除。官方没有给出基础佣金比例。
  3. 基础佣金来自第三方资料。现货基础佣金历史上是20%，持有500 BNB 及以上最高40%。2024年3月起，部分地区下调到10%到15%。合约是10%到20%。
  4. 有些第三方资料写可让出0%到50%，和官方最多20%的说法不一致。本集以官方为准。
Referral Split · 示例

10 USDT 手续费，拆进三个账户

  1. 来看分账流程。示例里，被推荐人成交一笔，付了10 USDT 手续费。这笔钱先全部进入平台手续费收入。
  2. 返佣服务按批次汇总，计算应返金额。返佣比例20%，就是2 USDT。推荐人又让出20%给被推荐人，于是2 USDT 拆成1.6加0.4。平台净收入剩8 USDT。
  3. 如果这个用户挂在经纪商下面，返佣服务还要算经纪商的份额。一个用户只能挂在一个上级下，关系在注册时绑定。这避免了同一笔手续费被返两次。
  4. 出错点在批次重跑。如果重跑时没有幂等键，同一批返佣会发两次。幂等键通常是用户加结算周期。第二次写入时，账本发现键已存在，直接跳过。
Restricted Asset · 科目名称为示例

体验金：独立的余额桶，只能流向少数地方

  1. 在任务中心，用户完成首次充值这类任务，就能领奖励。业界通常分四类：现金券、手续费抵扣券、体验金和理财加息券。只有现金券能提现。
  2. 重点看体验金。关键设计是，它不进入用户的可用余额，而是进入一个独立的余额桶。示例里，平台从营销预算账户发放100 USDT 体验金，进入用户的体验金桶。
  3. 体验金只能做一件事，就是作为合约保证金开仓。提币、划转、闪兑都碰不到它。因为提币服务只读可用余额，从结构上就提不走。
  4. 平仓有两种结果。亏损了，亏掉的部分回到营销预算。盈利30 USDT，盈利先进入待解锁。满足交易量或持仓时间的条件后，才转进可用。这是为了防止开仓即平仓的套利。
  5. 还有一条规则必须写清楚。亏损先扣体验金，还是先扣自有资金？不写进规则，就会出现自有资金先亏光、体验金还剩的争议。具体以活动页面为准。
State Machine · Marketing ROI

一次性燃料：只能被消耗或收回

  1. 把体验金的一生画成状态机。完成任务后发放，用户领取。没领取就过期。领取后作为保证金开仓，进入使用中。
  2. 平仓后还有剩余，就回到已领取。亏损用尽，就是已耗尽。到期或提取盈利时，剩余的体验金被收回。它不能变成可用余额。
  3. 有个细节。使用中如果到期，系统不能直接收回，因为仓位还在用。通常做法是等平仓后再收回。
  4. 平台为什么愿意发？算一笔示例。发100 USDT 体验金，用户平均亏损60 USDT。这60才是平台的实际支出。用户在后续6个月产生300 USDT 手续费。营销 ROI 等于300除以60，等于5。账面发了100，实际成本只是用户亏掉的部分。
Acquisition Funnel · 宽度为示意

返佣和任务奖励，作用在漏斗的不同层

  1. 返佣和体验金，都是获客漏斗的一部分。顶部是币安学院和币安广场，用免费内容和社区带来流量。往下是访问官网、注册、完成 KYC 和首次充值。再往下是首笔交易、30天留存，最后是 VIP 和机构。
  2. 每一层都会流失用户。业界通常观察到，KYC 和首次充值是最大的两个流失点。
  3. 两种工具针对漏斗的不同层。推荐码在注册时归因，任务奖励在首充和首次交易时触发。各层转化率属于商业数据，币安没有公开。
Account Tree · 权限最小化

机构的账户树：一个出口，多把受限的钥匙

子账户：2019 年推出 · 企业账户和 VIP 3 及以上 · 最多 200 个 · 新闻报道，以官网为准
  1. 进入机构产品。VIP 用户通常还有专属客户经理、更高的 API 限频和提币额度。公开报道显示，币安2019年推出子账户。企业账户和 VIP 3 及以上用户可开通，最多200个，以官网为准。
  2. 看机构的账户树。一个 KYB 主体下，主账户是唯一的提币出口。下面挂着现货策略、合约策略、交易员 A 三个子账户。主子之间的划转是账本内部划转，不上链，也没有 gas。
  3. 风险是隔离的。子账户2的合约仓位被强平，不影响子账户1的资金。
  4. 权限要最小化。交易员的 API Key 只开交易，不开提币，还可以绑定 IP。就算 Key 泄露，攻击者也只能乱交易，转不走资金。
  5. 出错点在主账户的 Key。它若开了划转权限，泄露后资金会被集中到一个子账户。攻击者再用低流动性交易对转移价值。
Broker Program

经纪商：自己的前端，币安的流动性

  1. 再看经纪商计划。它面向交易平台、钱包和金融科技公司。经纪商用自己的品牌和前端，接入币安的流动性。收益是返佣分成，没有前期接入费用。
  2. 接入方式有两种。Link 经纪商，用户在币安有自己的账户，授权经纪商的前端代为下单。Exchange 经纪商，经纪商为每个终端用户创建子账户，用户不直接接触币安。
  3. 看 Exchange 模式的架构。经纪商后端维护一张映射表，用户 A 对应子账户1，用户 B 对应子账户2。订单经过 Broker API 进入撮合。返佣进经纪商主账户，不进终端用户账户。
  4. 再看调用链。经纪商用主 Key 签名创建子账户，身份服务校验权限和上限。再为子账户创建只能交易的 Key，从主账户划转示例1000 USDT。之后用子账户 Key 下单，进入风控和撮合。
  5. 两个要点。第一，终端用户的 KYC 责任在经纪商一侧，以合同为准。第二，映射表一旦错乱，用户 A 的资金会显示给用户 B。另外，API 限频是否共享，是经纪商谈判的重点。
Market Maker · Maker Rebate

负 Maker 费率：钱来自同一笔成交的 Taker

  1. 现在看做市商。根据币安公告，现货流动性提供者计划按周考核 Maker 成交量或占比。一个公开的入门条件是，周 Maker 成交量达到2500万美元。或者占比达到0.05%。
  2. 公告还显示，第4档 Maker 返佣从负0.01%调整为负0.008%。也就是0.8个基点。连续3周不达标的账户，会被移出计划。参数会调整，以公告为准。
  3. 负费率怎样记账？示例是一笔10000 USDT 的成交。Taker 付0.10%手续费，也就是10 USDT，进入平台手续费收入。
  4. 平台从中按0.008%拿出0.8 USDT，返给做市商。平台净收入9.2 USDT。负费率不是凭空发钱，它来自同一笔成交的 Taker 手续费。只要 Taker 费率大于 Maker 返佣，平台每笔都赚钱。
  5. 出错点是自成交。做市商用自己的单吃自己的单，制造虚假成交量。平台需要自成交防护 STP 来阻止。

更高限频 · 专用 WebSocket · 批量下单 · FIX → 公平性争议
  1. 拿了返佣，做市商要承担义务。下面都是示例门槛。挂单时间占比不低于90%，最大价差不超过0.1%。盘口正负1%内的挂单金额，不低于5万 USDT。
  2. Maker 成交占比不低于0.05%。还有一条常被忽略：极端行情在线率不低于70%。行情剧烈时撤单，恰恰是做市商最想做的事。
  3. 做市商还关心延迟。传统交易所提供主机托管，延迟可以低到微秒级。加密交易所多部署在公有云。公开讨论普遍认为，币安的主要服务器在 AWS 东京区域，币安没有正式公开。
  4. 交易所还提供更高限频、专用 WebSocket、批量下单和 FIX 接入。这带来公平性争议。做市商比普通用户更早看到行情，也更快撤单。
Off-Exchange Settlement · 示例

资产留在托管方，交易所只给镜像额度

  1. 最后看场外结算。FTX 倒闭以后，机构最关心一个问题。交易所倒了，我的资产怎么办？场外结算的答案是，资产不进交易所钱包。
  2. 示例流程。机构把100 BTC 存进第三方托管，指定用于币安交易。托管方签名通知币安，100 BTC 已锁定。币安给机构账户100 BTC 的镜像额度。
  3. 交易周期内，机构在币安正常下单。盈亏都记在镜像账户上，不发生链上转账。
  4. 结算周期到了，机构净亏损2 BTC。托管方从机构的托管账户，划2 BTC 到交易所的托管账户。镜像额度更新为98 BTC。结算是批量、净额的，比逐笔上链便宜得多。
  5. 风险反过来了。机构在两次结算之间，可能亏损超过托管额度。交易所要实时监控保证金，在结算前要求追加。公开方案有 Ceffu MirrorX 和 Banking Triparty。2025年还加入了 USYC 和 cUSDO 作为抵押品。

考核漏洞

只看周平均挂单时间 → 关键时刻撤单仍达标 · 加极端行情在线率
  1. 把这一集的风险收拢一下。增长侧的第一个风险是自我推荐。用户用小号推荐自己，相当于自己给自己打折。平台用设备指纹和 KYC 关联来识别。
  2. 第二个是对敲刷量。推荐人和被推荐人互相成交，制造手续费换返佣。返佣比例低于100%，纯对敲是亏钱的。但叠加营销奖励之后，就可能有利可图。
  3. 机构侧的故障，多出在边界上。批次重跑没有幂等键，返佣发两次。经纪商映射表错乱，资金显示给错的人。主账户 Key 开了划转，泄露后资金被转移。
  4. 还有一个考核漏洞。如果只看周平均挂单时间，做市商可以平时多挂，在关键时刻撤单，仍然达标。所以要加极端行情在线率这类指标。

幕后核心 · 7 集
  1. 小结三点。第一，返佣和营销都是把手续费让出去。返佣靠绑定关系和幂等键防止多发，体验金靠独立余额桶防止被提走。
  2. 第二，机构的账户树按权限最小化设计。子账户隔离风险，交易 Key 不开提币，经纪商负责终端用户的映射。
  3. 第三，做市商的负费率来自 Taker 手续费。场外结算把资产留在托管方，交易所改为承担结算之间的信用风险。
  4. 产品深潜到这里就结束了。下一季，我们进入幕后核心，一共7集。合规、平台安全、账户安全、系统对账、业务风控、金库与流动性，最后是应急响应。
  5. 这些系统不产生收入，但决定交易所能不能活下去。下一集是 B01 合规防护。我们从 KYC、反洗钱和 Travel Rule 讲起。
