  2. 业务风控不同。这类风险看不出单笔异常，只在一群账户、一段时间、一批订单里显现。所以它以异步检测和事后处置为主。
  3. 打个比方，交易所像大商场。门口安检查危险品，业务风控是保安监控室。30个人办了30张会员卡，领完赠品就走，这是羊毛党。摊位摆满货，顾客一靠近就收，这是幌骗。两个摊主互相买卖刷销量，这是对敲。
  4. 但这个比喻有不准的地方。商场保安能当场拦人。监控引擎运行在撮合之后，它发现操纵时，操纵往往已经完成。

防线分层

每一层都会漏，漏的东西不同

第 1 层 准入KYC 一人一号、设备指纹漏：购买来的实名账户
第 2 层 实时STP、价格保护带、持仓限额漏：不同账户之间的对敲
第 3 层 检测撤单率、关联成交、量价突增漏：低频、跨平台操纵
第 4 层 调查图关联分析、人工调查、证据留存发现时损失多已发生
第 5 层 处置取消奖励、冻结收益、做市商下线、监控标签、下架
设计原则：检测有延迟 → 奖励发放后置，给检测留时间。
  1. 再看防线。业务风控分五层。第1层是准入，靠 KYC 一人一号和设备指纹，拦住一个人注册很多号。
  2. 它漏过的是买来的实名账户。KYC 是真的，只是账户被买卖了。
  3. 第2层是实时规则，比如自成交预防 STP、价格保护带和单账户持仓限额。它同步执行，只能处理同一账户的问题。两个关联账户之间的对敲，它挡不住。
  4. 第3层是准实时检测，盯撤单率、关联成交和量价突增。第4层是事后调查，做图关联和人工取证。它们发现问题时，损失往往已经发生。
  5. 第5层是处置。取消奖励、冻结收益、做市商下线、加监控标签，直到下架。
  6. 由此得出一条设计原则。检测有延迟，奖励发放就要后置，给检测留出时间。
营销反作弊 · 示例数字

把账户画成图，团伙就是连通分量

  1. 先看营销反作弊。作弊的经济账很简单。举个示例，新账户奖励10 USDT，注册和养号成本3 USDT。每个号净赚7 USDT，1万个号就是7万 USDT。只要奖励大于成本，就一定有人批量注册。
  2. 怎么识别？第一类信号是设备。比如200个账户只共享5个设备指纹，或者用了模拟器和改机工具。
  3. 第二类是网络和行为。注册集中在同一个 IP 网段。每个账户都在注册后3分钟，完成同一套任务。真人的操作不会这么整齐。
  4. 第三类信号最稳定，是资金归集。领完奖励后，这些账户把钱转给同一个账户。这是羊毛党变现的必经之路。
  5. 把这些信号画成一张图。账户是节点，共享设备、IP、地址和转账是边。连通分量大的子图，就是疑似团伙。旁边零散的节点，是正常用户。
奖励发放后置 · 示例

评分完成之前，奖励不进可用余额

  1. 用户完成任务后，系统不直接发钱，只记一条待发奖励。奖励不进可用余额。
  2. 接着进入冷静期，举个示例，7天。这段时间里，反作弊模型和图关联持续给账户打分。
  3. 冷静期结束，按分数分流。低风险自动发放，中风险进入人工审核，高风险或团伙命中直接取消。
  4. 中风险为什么要人工通道？因为被误拒的真实用户会投诉，人工审核是给误判留的出口。
  5. 如果奖励已经发放，事后才确认作弊，就进入追回，冻结奖励及其收益。但追回的前提是钱还在平台内。作弊者通常领完就提走，所以后置比追回更重要。
  6. 冷静期是个权衡，越长检测越准，真实用户体验越差。规则 MKT-06 是个例子。同一设备指纹有5个以上账户领同一奖励，就转人工审核。
市场监控 · Spoofing · 示例订单簿

挂出来不是为了成交，是为了被看见

  1. 进入市场监控。先看幌骗，英文叫 spoofing。这是一个示例订单簿，盘口每档的平均挂单量约2个 BTC。
  2. 操纵者在买一下方，突然挂出一笔12个 BTC 的大买单。看起来，买盘一下子变得很强。
  3. 其他人以为要涨，开始主动买入。操纵者挂在卖一的卖单被吃掉了。
  4. 卖单成交后，那笔大买单在1.6秒内就撤掉了。它从来没打算成交。
  5. 对照检测规则 MKT-01。订单量是均量的6倍，超过5倍。存活不到2秒。该账户撤单率95%，超过90%。撤单前对侧有成交。四条全中，触发告警。
  6. 它的变体叫分层挂单。同一账户在同一侧3个以上价位同时挂单，又同时撤销。注意，幌骗的证据在撤单里。所以监控引擎必须消费全部订单事件。
市场监控 · Wash Trading · 示例

两个账户互相成交，STP 拦不住

  1. 再看对敲，也叫 wash trading。账户 U7 和 U8 互相买卖。示例里成交量不断上涨，价格却几乎不动。
  2. STP 会拦截同一用户的自成交。但 U7 和 U8 是两个用户，STP 拦不住。
  3. 于是监控引擎去查两人的关联度。我们比较6个特征。设备指纹、IP、充值来源、提币地址、KYC 信息和下单时间。
  4. 两人共享其中5个。相似度等于5除以6，约0.83。这叫 Jaccard 相似度，是一个示例公式。
  5. 规则 MKT-02 的阈值是0.7。0.83超过阈值，触发告警，这些成交量也要从统计里剔除。分析师的结论会回填为真值标签，用来计算精确率和召回率。
市场监控 · Pump and Dump · 示例数字

量价突增，随后同一批账户净卖出

  1. 第三种操纵是拉盘砸盘。这是一个小币的示例走势，每根柱子是5分钟的成交量。平时的基线，大约每5分钟100万 USDT。
  2. 突然，一批账户集中买入。这5分钟的成交量到了450万，是基线的4.5倍。价格涨了12%。
  3. 跟风的买家进场，价格继续往上走。
  4. 随后，同一批账户集中净卖出，价格回落，跟风的人接了盘。
  5. 规则 MKT-03 这样写。5分钟成交量大于等于基线的4倍，并且涨幅大于等于8%，就告警。同时标记这一时段大额净买入的账户。

  3. 再看资产风险。第一类是稳定币脱锚。2022年5月 UST 崩溃，2023年3月 USDC 短暂跌破1美元。规则 AST-01 是，偏离1美元2%以上并持续10分钟，就降低抵押折算率。

  5. 第三类是项目方风险，靠监控标签处理。币安对风险明显偏高的代币加监控标签。用户交易前要通过风险测验，每90天重测一次。
  6. 标签是下架前的黄灯，指标恢复就回到持续监控。持续不达标，就公告下架，并保留提币窗口。严重事件可以直接下架。
风险参数治理

改一个数字影响全部用户，要像代码一样审

  1. 风险参数包括杠杆上限、保证金率、借贷限额和指数权重等。改一个数字，影响全部用户。
  2. 所以参数要像代码一样治理。先提出变更，附上影响评估。再做独立复核，用历史行情回测，看会多出多少强平和穿仓。
  3. 然后审批，提出人和审批人必须分开。批准后先走灰度或影子模式，再正式生效并公告。
  4. 每次变更都写审计日志，记下谁、何时、旧值和新值。复盘时才能回答，那一刻的参数是什么。
  5. 紧急时，比如稳定币脱锚，值班风险官可以立即降低折算率，24小时内补审批。
  6. 注意，紧急路径只允许收紧风险。降杠杆、降限额可以走这条路。放宽风险，必须走正常审批。

  1. 来看一个完整案例。据公开报道，这是2024年6月 Lista DAO 的 Megadrop 活动。币安在活动中识别出大量作弊账户。
  2. 作弊者批量购买了已实名的账户，每个账户都参加活动。所以第1层 KYC 没有拦住。
  3. 领到奖励代币后，他们把代币归集到同一个账户，准备卖出。

局限与权衡 · 小结

每个阈值都是一次取舍

权衡一端另一端
误杀 vs 漏放撤单率阈值低：抓到更多幌骗正常做市商被误报
体验 vs 反作弊奖励即时到账：拉新好羊毛党领完即走
透明 vs 对抗公开规则：用户可预期作弊者按规则调整
平台利益 vs 市场公平刷量抬高排名和手续费误导用户，招致处罚

记住三件事

  • 看一群账户、一段时间、一批订单；奖励后置，给检测留时间。
  • 幌骗看撤单，对敲看关联度，拉盘看量价，内幕看时间。
  • 风险参数像代码一样治理：提出与审批分离，紧急只许收紧。

  1. 最后看权衡。第一对是误杀和漏放。撤单率阈值调低，能抓到更多幌骗，但正常做市商会被误报。
  2. 体验和反作弊也是一对。奖励即时到账，拉新效果好，但羊毛党领完就走。公开规则让用户可预期，也让作弊者调整行为。
  3. 还有平台利益和市场公平。刷量能抬高排名，但虚假成交量误导用户，还会招来处罚。
  4. 小结三点。第一，业务风险看不出单笔异常。要看一群账户、一段时间、一批订单，并且让奖励后置。
  5. 第二，市场监控消费全部订单事件。幌骗看撤单，对敲看关联度，拉盘看量价，内幕看时间。
  6. 第三，风险参数像代码一样治理。提出和审批分离，紧急路径只许收紧。
  7. 下一集是 B06 金库与流动性，看用户的钱放在哪里，挤兑来了付不付得出。也可以先打开市场监控实验，拖动阈值试一试。
