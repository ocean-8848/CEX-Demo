储备金证明（Merkle 树）

交易所把每个用户的余额做成一个叶子，两两哈希，层层向上，得到一个根哈希并公开。你只需要自己的余额和几个"兄弟哈希"，就能自己算出根哈希，确认你的余额被计入了负债。本页用浏览器自带的 SHA-256 实时计算。用户和金额都是示例。

怎么玩

  1. 在左侧表格里查看或修改 8 个示例用户的余额。修改后，交易所重新构建树并发布新根哈希。
  2. 点击表格里的一行，或点击树底部的叶子，选中一个用户。树上会高亮他的 Merkle 路径（证明）。
  3. 在"自行验证"面板点击"开始验证"，逐步看到从叶子算到根的过程。
  4. 点击"偷偷篡改余额"或"塞入负余额假账户"，观察哪些检查能发现问题，哪些不能。

4. 自行验证（站在用户角度）

你只用到三样东西：自己的 UID 和余额、交易所给你的兄弟哈希列表、公开根哈希。你看不到其他用户的余额。

    5. zk-SNARK 约束检查（模拟）

    Merkle 证明只回答"我在不在树里"。zk-SNARK 证明额外回答两件事，而且不公开任何用户余额。本面板直接检查这两条约束，用来模拟证明的效果，不是真实的零知识证明。

      为什么需要它？ 交易所可以塞入一个余额为负数的假账户。每个真实用户的 Merkle 验证仍然全部通过，但负债总额被压低，储备率看起来更高。只有"所有叶子 ≥ 0 且总和 = 公布负债"这条约束能抓住它。币安于 2023 年 2 月在 PoR 中加入 zk-SNARK，正是为了证明这两点（公开资料）。
      试一试
      1. 选中 U1003，点"开始验证"。数一数，8 个用户的树需要几个兄弟哈希？
      2. 保持选中 U1003，点"偷偷篡改余额"，再验证一次。然后换成 U1006 验证。为什么只有被篡改的用户能发现问题？这说明为什么需要大量用户去验证？
      3. 点"塞入负余额假账户"。所有真实用户的验证都通过了吗？储备率发生了什么变化？看 zk-SNARK 面板如何发现问题。

      6. 储备金证明的局限

      • 只是某一时刻的快照。交易所可以在快照前借入资产，快照后还回去。
      • 不证明负债完整。交易所可能漏掉从不验证的账户。Merkle 树只能证明"在树里"，不能证明"所有人都在树里"。
      • 不证明资产没有借入或抵押。链上地址有余额，不代表这些资产没有对应的链下负债。
      • 不覆盖链下负债。例如交易所对机构的借款、法币负债，不在用户余额树里。
      • 依赖用户参与。验证的用户越少，被篡改却不被发现的概率越高。
      教学简化：币安的真实叶子包含用户 ID 哈希和多个币种的净余额，树的规模达到数千万叶子；本页用单一币种、8 个示例用户。链上资产 100 BTC 为示例值。
